### 1. CS336 BPE训练过程

##### **第一步：建立初始词表**

先在词表中放入 256 个基础字节 token，覆盖从 0 到 255 的所有字节值，对应的 token ID 也是 0 到 255。因此，训练刚开始时，字节值恰好就是 token ID。

需要区分字节和字符：一个英文字母通常对应一个 UTF-8 字节，一个汉字通常对应多个字节。因此，初始阶段一个汉字通常需要多个基础 token 表示。

随后，对输入的特殊 token 按首次出现的顺序去重，将它们编码为 UTF-8 bytes，并从 ID 256 开始依次加入词表。特殊 token 占用词表额度，但不参与普通文本的 BPE 合并。

目标 `vocab_size` 包含基础字节、特殊 token，以及之后通过合并产生的 token。如果目标大小小于初始词表大小，就报错；如果两者相等，就不需要产生新的合并 token。

##### **第二步：读取语料，并在需要时分块处理**

为了处理较大的语料，可以先将文件划分为多个块，分别读取、解码和预分词。

你的实现只有在 `<|endoftext|>` 被声明为特殊 token 时，才使用它对齐文件块边界：先根据文件大小估计分块位置，再向后扫描找到分隔符，将边界放在分隔符的起始位置。重复的边界会被去掉，因此实际块数可能少于预期。

如果没有声明这个特殊 token，就将整个文件作为一个块处理。

不同块的读取、UTF-8 解码和预分词可以通过多个进程并行完成，之后将各块的统计结果汇总。BPE 合并阶段在主进程中串行执行。

文件分块是读取和计算安排；后面仍然依据整份语料汇总后的频次，统一学习合并规则。

##### **第三步：按特殊 token 隔开普通文本**

对每个读取并解码后的文本块，先识别特殊 token，以它们为边界切分文本，并从训练文本片段中移除这些标记。

匹配时，特殊 token 按字面内容识别；同一位置优先匹配较长的特殊 token，避免较短的前缀提前截断较长标记。空字符串不允许作为特殊 token。

例如，`hello<|endoftext|>world` 会得到两个独立片段：“hello”和“world”。

移除分隔符后，两个片段仍然保持独立，不会拼接成“helloworld”。后续统计和合并都不能跨过这个边界。切分产生的空片段会被跳过。

特殊 token 仍然保留在词表中，供编码时识别；这里只是将它们排除在普通文本的训练统计之外。

##### **第四步：对普通文本进行 GPT-2 预分词**

对每个普通文本片段，使用 GPT-2 正则规则，将它划分为若干预分词单元，也就是 pre-token。

例如，“hello world!”可以划分为：

- “hello”
- “ world”
- “!”

其中，“ world”前面的空格属于这个预分词单元。

预分词单元不一定等于日常语言中的一个词，具体边界由正则规则决定。它为后续 BPE 规定了合并范围：**只能在同一个预分词单元内部统计和合并相邻 token，不能跨越单元边界。**

因此，“hello”末尾的字节不能与下一个单元开头的空格合并，但“ world”内部的空格可以与后面的字节逐步合并。

你的实现还会检查：将所有正则匹配结果按顺序拼接后，应当恢复原来的普通文本片段，确保没有遗漏字符。

##### **第五步：将预分词单元转换为初始 token 序列，并汇总频次**

将每个预分词单元编码为 UTF-8 字节序列，再根据初始词表，将这些字节表示为 token ID 序列。

例如，“hello”对应的初始序列是：

104、101、108、108、111。

如果“hello”在语料中出现了 100 次，就只保存一条这样的序列，并记录其出现次数为 100。相同序列的次数会累加，包括来自不同文件块的相同序列。

最终得到一张全局频次表，记录：

**每一种不同的预分词 token ID 序列，以及它在语料中的出现次数。**

后面的训练直接在这张频次表上进行，不需要每轮重新读取原文。随着合并发生，序列中会出现新 token ID；此时，序列元素就不再全是 0–255 的基础字节值。

##### **第六步：建立相邻 pair 的全局频次统计**

在每条序列内部，统计每一对相邻 token 的出现次数，并乘以该序列的语料频次，最后在所有序列之间求和。

下面用字母表示基础字节 token，用空格表示 token 之间的分界。假设频次表只有两条序列：

| token 序列 | 语料出现次数 |
| ---------- | ------------ |
| a b a b    | 3            |
| a b c      | 2            |

在第一条序列中，`(a, b)` 出现两次，贡献 \(2 \times 3 = 6\) 次；`(b, a)` 出现一次，贡献 3 次。

在第二条序列中，`(a, b)` 和 `(b, c)` 各出现一次，各贡献 2 次。

汇总结果为：

| 相邻 pair | 全局频次 |
| --------- | -------- |
| (a, b)    | 8        |
| (b, a)    | 3        |
| (b, c)    | 2        |

这里统计的是相邻位置的出现次数，并且包含重叠窗口。例如，序列 `a a a` 中，`(a, a)` 出现两次。

你的实现同时记录每个 pair 出现在哪些不同的序列中，形成倒排索引。后续选中一个 pair 时，就能直接找到需要处理的序列。

全量 pair 统计在合并循环开始前建立一次，之后通过增量更新维护。

##### **第七步：选择最佳 pair，创建新 token，并记录规则**

选出当前全局频次最高的相邻 pair。

如果多个 pair 的频次相同，先比较左 token 对应的 bytes；左边相同时，再比较右 token 对应的 bytes，选择字典序较大的 pair。比较对象是左右 bytes 构成的二元组。

在上面的例子中，选择的是 `(a, b)`。将两者的 bytes 拼接，得到新 token `ab`，分配一个新的 ID，并加入词表。

旧 token `a` 和 `b` 仍然保留在词表中。每轮合并只新增一个词表条目。

同时，将这次合并的左右 bytes 作为一条规则，追加到 `merges`。规则按照训练发生的顺序保存，这个顺序决定了以后编码时的合并优先级。

你的优化版使用优先堆选取当前最佳 pair，但选择依据仍然是当前频次及上述平局规则。

##### **第八步：在受影响的序列中进行非重叠替换**

通过倒排索引，找到所有包含所选 pair 的序列，在每条序列内部从左到右进行替换。

沿用上面的例子，合并 `(a, b)` 后：

| 替换前  | 替换后 | 语料出现次数 |
| ------- | ------ | ------------ |
| a b a b | ab ab  | 3            |
| a b c   | ab c   | 2            |

这里的每个 `ab` 都表示一个新 token。

每条序列所代表的文本内容没有改变，语料出现次数也没有改变；改变的是表示这段文本所需的 token 数量及其相邻关系。

替换必须非重叠。例如，将 `(a, a)` 合成 `aa` 时，序列 `a a a` 会从左到右变为 `aa a`。中间的 `a` 已经参加了第一次合并，不能再参加第二次。

因此，**统计时允许计算重叠的相邻窗口，实际替换时不能重复使用同一个位置。**

##### **第九步：更新统计，并根据新统计继续合并**

替换完成后，需要更新相邻 pair 的全局频次。

你的实现只处理受影响的序列：先撤销这些序列在替换前对全局 pair 计数的贡献，再加入替换后序列的贡献，同时更新序列频次表和倒排索引。其他序列的贡献保持不变。

这里会重新统计每条受影响序列内部的全部相邻 pair。频次降到零的 pair 会被移除，倒排索引中的空项也会被清理。

在例子中，替换后的统计变为：

| 相邻 pair | 全局频次 |
| --------- | -------- |
| (ab, ab)  | 3        |
| (ab, c)   | 2        |

如果词表尚未达到目标，下一轮就选择 `(ab, ab)`，创建新 token `abab`，再将第一条序列替换为单个 `abab` token。

这说明，BPE 不仅可以合并基础字节，还可以继续合并前面已经产生的 token，逐步形成更长的 token。

每轮都必须依据更新后的全局频次选择下一对。优化版也会同步维护优先堆，选取时丢弃失效的旧条目。

##### **第十步：满足停止条件后，返回训练结果**

训练反复执行：

**依据当前统计选 pair → 创建新 token 并记录规则 → 替换受影响序列 → 更新统计。**

遇到以下任一条件就停止：

- 词表大小达到目标 `vocab_size`。
- 已经没有相邻 pair 可以合并。

因此，最终词表可能小于目标大小，例如语料中的所有预分词单元都已经变成单个 token，却仍未用完词表额度。

训练最后返回两个结果：

| 结果     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| `vocab`  | token ID 到 bytes 的映射，包含基础字节、特殊 token 和训练新增的 token |
| `merges` | 按训练顺序保存的左右 bytes pair，记录每次合并及其优先级      |

之后编码新文本时，使用已经训练好的词表和合并优先级处理文本，再输出 token ID，不再重新统计语料频次或学习新规则。

### 2. 训练文本→Token ID

本阶段的目标是：**把训练文本变成磁盘上一串足够长的一维的token ids。**

用已经训练好的 tokenizer 编码大语料，就是使用固定的词表和合并规则，将文本按顺序转换为 token ID，再写入硬盘。编码过程中不再统计语料频次，也不学习新的 token。

##### **1. 流式读取文本，整理成可独立编码的片段**

大语料可能无法一次放入内存，因此可以一边读取、一边编码、一边写盘。

读取块只是 IO 单位，不一定适合直接编码：一篇文档可能跨越多个读取块，特殊 token 也可能被读取边界切断。因此，需要保留尚未完整的尾部，与下一块拼接后再处理。

分段时，应确保切分不会改变特殊 token 的识别和普通文本的预分词结果。一种常见方式是在完整的、已注册的文档分隔符 `<|endoftext|>` 之后切开，并保留分隔符。文件末尾没有分隔符的剩余文本也需要编码，不应丢弃。

##### 2. 选择安全切点：只能切在完整文档边界上

因为GPT-2 预分词和 BPE merge 都发生在「一个 pre-token 内部」，若从单词中间、或从 `<|endoftext|>` 中间切开再分别编码，id 序列会和整篇一次编码不同。

因此**安全切点**必须是：完整的文档分隔符 `<|endoftext|>`。这样方便训练文档一段一段编码，并且按照原文顺序把token id连接起来。

##### **3. 区分普通文本与特殊 token**

对每个可独立编码的片段，先识别特殊 token，将其与普通文本分开，并保持原有顺序。

- 特殊 token 直接映射为词表中的一个固定 ID，不进行预分词，也不参与 BPE 合并。
- 普通文本进入后续预分词和合并流程。

例如，`hello<|endoftext|>world` 中的两段普通文本分别编码，中间保留一个特殊 token ID，不会将两侧拼成 `helloworld`。

这里与 BPE 训练不同：训练时将特殊 token 排除在 pair 统计之外；编码时必须保留它们，并输出对应 ID。

##### **4. 将普通文本划分为 pre-token**

使用与训练时相同的 **GPT-2 正则**规则，将普通文本划分成若干预分词单元，也就是 pre-token。

例如，“hello world!”可以划分为“hello”、“ world”和“!”。其中，“ world”开头的空格也是该单元的一部分。

pre-token 不一定等于日常语言中的一个词。它规定了 BPE 的合并范围：**后续合并只发生在各个 pre-token 内部，不跨越它们的边界。**

##### **5. 将每个 pre-token 转为字节 token，再应用合并规则**

先将每个 pre-token 编码为 UTF-8 字节序列，再查询词表，得到各个单字节对应的初始 token ID。对于训练出的词表，这些基础 ID 是 0–255，与字节值一致。

随后，在这个 pre-token 内反复进行以下处理：

- 查看当前序列中的相邻 pair，找出已经登记在训练合并规则中的 pair。
- 选择其中训练排名最靠前、也就是优先级最高的一种 pair。
- 从左到右，将这种 pair 的所有非重叠出现替换为合并后的 token ID。
- 根据更新后的序列重新选择，直到没有可用规则，或者只剩一个 token。

**训练排名决定先合并哪一种 pair；从左到右决定选中 pair 的替换顺序。** 不能只因为某个 pair 出现在更靠左的位置，就优先合并它。

合并后的 token 及其 ID 已经存在于词表中，编码时只查询并使用它们，不创建新的词表条目。整个合并过程不跨 pre-token 边界。

这里需要区分：

- **合并优先级**决定先选择哪一种 pair。
- **从左到右、非重叠**决定选中 pair 后怎样替换它的出现位置。

例如，将 `(a, a)` 合成 `aa` 时，`a a a` 会变成 `aa a`，中间的 `a` 不能使用两次。新得到的 token 还可以继续参与后续合并。

合并后的 token 和 ID 都已经存在于词表中，编码只使用它们，不增加词表条目。

##### **6. 按原文顺序形成一维 token ID 流，并分批写入磁盘**

将各个 pre-token 的编码结果、特殊 token ID，以及不同文本片段的结果，按照原文顺序连接起来，形成一维 token ID 流。

不需要等整份语料编码完成才保存，可以积累一批 ID 就写入硬盘，最后写出剩余部分。存储类型需要能够容纳全部 ID，后续读取时使用相同的数据类型。

##### **7. 语言模型直接使用编码后的 ID 序列训练**

编码完成后，语言模型可以直接从 ID 文件中读取连续窗口，不再读取原文或执行 BPE。

输入窗口中的每个 token，以它后面的 token 为预测目标。如果采用连续切窗，窗口可以跨越文档分隔符；保留文档结束 token，并不意味着必须在此处截断训练样本。

训练、验证和后续生成应使用同一套 tokenizer，确保每个 ID 始终对应相同的内容；模型的词表维度也必须覆盖这些 ID。

### 3. 从一维 token id 流到 embedding 向量

**1．准备好编码后的训练语料。**

Tokenizer 已经把原始文本转换成一条很长的 token ID 序列，并保存到磁盘。

这些 ID 按照原文顺序排列。每个 ID 代表词表中的一个 token，但**编号的大小本身不表示含义**。

接下来，语言模型训练使用这些编号作为输入。

**2．训练开始前，创建一张 Embedding Table。**

这张表为词表中的每个 token 准备一个向量：

- **行数由 `vocab_size` 决定：**词表有多少个 token，表就有多少行。
- **列数由 `d_model` 决定：**每个 token 用多少个数表示。

例如，词表有 10,000 个 token，`d_model = 512`，就创建一张 **10,000 行、512 列**的表。

从零训练时，表中的数值随机初始化，此时还没有学到有用的语言表示。

**这张表只初始化一次，之后所有批次共用，并在训练过程中持续更新。**

**3．每个训练步，从长序列中取出一批样本。**

整份语料很长，每一步只取出一部分交给模型处理。

具体做法是：随机选择 `batch_size` 个合法起点，从每个起点开始，**按原文顺序连续截取 `context_length` 个 token ID**。

其中：

- `batch_size` 决定一次处理多少条样本。
- `context_length` 决定每条样本有多少个 token。

例如，`batch_size = 32`、`context_length = 256`，就是一次取出 **32 条样本，每条包含 256 个 token**。

随机的是起点，片段内部的顺序保持不变。不同片段可以重叠。

**4．同时准备每个位置对应的“正确答案”。**

语言模型的任务是：**根据已经看到的内容，预测下一个 token。**

因此，对于每条输入，还要准备一条向后错开一个 token 的目标序列。

假设某段连续内容是：

```
我　喜欢　机器　学习
```

为了方便理解，假设这里每个词恰好都是一个 token。如果每条输入取 3 个 token：

```
输入：我　　喜欢　机器
答案：喜欢　机器　学习
```

对应的训练任务是：

| 模型看到的内容 | 应该预测 |
| -------------- | -------- |
| 我             | 喜欢     |
| 我 喜欢        | 机器     |
| 我 喜欢 机器   | 学习     |

因此，每个起点后面至少需要 **`context_length + 1` 个 token**，多出的最后一个用于提供最后一个位置的答案。

**5．用输入 ID 查表，把每个编号替换成向量。**

准备好一批输入后，每个 token ID 就作为行索引，取出 Embedding Table 中对应的一行。

例如，某个 token 的 ID 是 `42`，就取出表中索引为 `42` 的那一行。若 `d_model = 512`，这一行就是包含 512 个数的向量。

整个 batch 的形状变化为：

```
(batch_size, seq_len)
变成
(batch_size, seq_len, d_model)
```

这里的 `seq_len` 就是这批样本的实际长度，在你的训练取样中等于 `context_length`。

**样本数量、token 数量和顺序都没有改变，只是每个编号被替换成了一个向量。**

同一个 token 在不同位置出现，刚查表时得到的向量相同。查表本身还没有结合上下文。

**6．向量进入 Transformer，结合上下文进行预测。**

这些向量进入 Transformer 后，模型逐层处理它们，结合位置信息和前面的内容，形成新的隐藏向量。

因果注意力保证每个位置只能看到自己和前面的 token，不能偷看后面的答案。

最后，输出层根据每个位置的隐藏向量，给词表中的所有候选 token 打分，用来预测下一个 token。

因此，**相同 token 刚查表时向量相同，但经过 Transformer 后，可以因为上下文不同而得到不同的隐藏向量。**

**7．根据预测与正确答案的差距，更新模型参数。**

模型将预测结果与提前准备好的答案比较，计算损失，衡量预测错了多少。

接着：

- **反向传播**计算模型各个可学习参数的梯度。
- **AdamW 优化器**根据梯度及其保存的状态调整参数。

更新的参数既包括 Embedding Table，也包括 Transformer 和输出层等部分的参数。

Embedding Table 中的数值因此逐渐变得更有助于预测下一个 token。**训练过程中，输入的 token ID 和编码后的语料保持不变。**

**8．使用更新后的模型，继续处理下一批数据。**

下一步重新抽取一批样本，用更新后的 Embedding Table 查表，然后继续预测、计算损失和更新参数。

所以，**Embedding 从第一步训练就开始查表，并在一次次预测和纠错中逐渐学好。**

训练完成后，推理时加载整个训练好的模型，包括其中的 Embedding Table。新输入经过同一个 tokenizer 编码后，仍然通过查表转换成向量，再送入 Transformer 进行预测。

### 4. TransformerBlock骨架（pre-norm）

##### **1. 经过 embedding 后，进入 TransformerBlock**

经过 embedding 查表，每个 token 被表示为一个包含 `d_model` 个数的隐藏向量。整个 batch 的形状为：

\[ (\text{batch\_size},\ \text{seq\_len},\ d_{\text{model}}) \]

其中，`batch_size` 是这一批序列的数量，`seq_len` 是每条序列中的 token 数量，`d_model` 是每个 token 的隐藏表示维度。

第一层 TransformerBlock 接收 embedding 的输出；后续 Block 接收上一层更新后的隐藏表示。

##### 2. 分支一：保留输入，形成残差分支

进入 Attention 子层时，保留当前输入作为**残差分支**；另一条计算路径先经过 RMSNorm，再进入 Attention。

残差分支保留的是当前子层**归一化之前**的输入。等 Attention 计算完成后，将其输出与这个输入逐元素相加，使子层能够在已有表示的基础上学习更新，同时为梯度传播提供直接路径。

**3.分支二： 对每个 token 的隐藏向量独立进行 RMSNorm**

RMSNorm 沿最后一个维度计算。对每个 token，它先将隐藏向量中的各个数平方、求平均，再加上一个小常数 \(\epsilon\) 并开平方，得到衡量该向量数值尺度的分母。

然后，将这个向量的每个分量除以同一个分母，再分别乘以对应的可学习缩放参数：
$$
\operatorname{RMSNorm}(x) = \frac{x} {\sqrt{\frac{1}{d_{\text{model}}}\sum_{i=1}^{d_{\text{model}}}x_i^2+\epsilon}} \odot g
$$
其中：

- `x`：一个 token 的隐藏向量
- `d_model`：隐藏向量的特征数量
- `ε`：防止除以零的小常数
- `g`：可训练的缩放参数，也就是代码中的 `self.weight`
- `⊙`：逐元素相乘

每个 token 根据自己的隐藏向量计算尺度，不与其他 token 或其他样本混合统计。同一层的缩放向量 \(g\) 则在所有 token 位置之间共享，通过训练学习各个特征维度适合的缩放程度。

RMSNorm 不减去均值，也不要求最终输出的均值为 0、方差为 1。它的作用是控制进入后续子层的表示尺度，帮助计算和训练保持稳定。

##### 4. 归一化调整数值尺度，不改变形状

归一化只改变数值，不改变 token 数量或隐藏维度，因此输出形状仍然是：

\[ (\text{batch\_size},\ \text{seq\_len},\ d_{\text{model}}) \]

这一步的作用是调整进入 Attention 的隐藏表示尺度，让后续计算更稳定。它本身不进行 token 之间的信息交互；每个位置只使用自己的隐藏向量完成归一化。

##### 5. Attention 使用归一化后的表示，输出加回原输入

归一化结果进入 Attention，再分别经过线性投影生成 Q、K、V。

这里没有在 RMSNorm 后向隐藏状态加上位置向量。采用 RoPE 时，位置信息会在后续 Attention 内部作用于 Q、K。

Attention 计算完成后，将其输出与之前保留的、归一化前的 \(x\) 逐元素相加：

\[ h=x+\operatorname{Attention}\bigl(\operatorname{RMSNorm}_1(x)\bigr) \]

因此：

**Attention 使用的是 RMSNorm 后的表示，残差加回的是 RMSNorm 前的原输入。**

Attention 分支学习的是对已有表示的更新。相加后，既保留原来的表示，也加入本次计算得到的信息；反向传播时，梯度还可以沿残差分支直接传回，不必全部经过 Attention。

##### **6. 接下来进入第二个子层**

得到更新后的隐藏状态 \(h\) 后，再保留 \(h\) 作为第二条残差分支。另一条路径经过独立的第二次 RMSNorm，再进入 SwiGLU，最后与 \(h\) 相加。

两次归一化各有自己的参数：第一次服务于 Attention，第二次服务于前馈网络。这里讲解的是启用 RMSNorm 的默认 pre-norm 结构，不包含禁用归一化或改用 post-norm 的实验路径。

### 5. TransformerBlock骨架: 多头因果注意力（pre-norm里的Attention）

**多头因果注意力的作用是：让每个 token 根据当前位置及之前的内容，提取对自己有用的信息。**

在 pre-norm 结构中，先保留进入注意力子层前的原始输入 `x`，用于最后的残差连接；再对 `x` 进行 RMSNorm，将归一化后的结果送入 Attention：
$$
z=RMSNorm_1(x)
$$
这里的 `x` 是当前 TransformerBlock 的输入隐藏状态。如果前面已经经过其他 Block，它就已经包含前面各层提取的上下文信息。

**此时只是保留了残差分支，尚未进行残差相加。** Attention 使用的是归一化后的 \(z\)，形状为：
$$
(\text{batch\_size},\ \text{seq\_len},\ d_{\text{model}})
$$

以下统一使用：

- `B`：`batch_size`，这一批包含多少段文本。
- `T`：`seq_len`，每段文本包含多少个 token。
- `H`：`h_heads`，注意力头的数量。
- `D`：`d_head`，每个头中每个 token 的向量宽度。

它们满足：
$$
d_{\text{model}}=H\times D
$$


##### 1.  用三组线性投影生成 Q、K、V

调用**线性映射函数(Linear)**，把经过RMSNorm的输入分别转化成Q、K、V。

对每个位置的 d_model 向量，用三套不同权重映到同一宽度：
$$
Q = z W_Q^\top,\quad
K = z W_K^\top,\quad
V = z W_V^\top
$$
形状都是：
$$
(B,T,d_{\text{model}}）
$$
其中：
$$
W_Q,W_K,W_V \in\mathbb{R}^{d_{\text{model}}\times d_{\text{model}}}
$$
同一份输入分别经过三套不同的线性变换，得到 Q、K、V。

- **Q**：用来寻找相关信息。
- **K**：用来与 Q 匹配。
- **V**：提供最后要提取的内容。

还没拆头时，可以想成「所有头的 Q 拼在最后一维里」，K、V 同理。

##### 2.  拆头：把Q、K、V最后一维最后一维拆成头数和每头宽度

此时，每个 token 的 Q、K、V 向量都是 `d_model` 维，也就是说，每条向量包含 `d_model` 个**数值分量**。

把每条向量平均分成 `h_heads` 份，那么，每份中包含的数值分量数量为：
$$
d_{\text{head}} = \frac{d_{\text{model}}}{h_\text{heads}}
$$
因此，`d_model` 必须能够被注意力头数 `h_heads` 整除。

Q、K、V 分别进行相同的形状调整：

```
(batch, seq_len, d_model) 
→ (batch, seq_len, h_heads, d_head)
```

也就是：
$$
(B,T,d_{\text{model}}) \longrightarrow (B,T,H,D)
$$
**这里拆分的是每个 token 的向量，不是把整段序列分给不同的头。** 每个头仍然包含全部 `T` 个 token，只是每个 token 在这个头中用 `D` 个分量表示。

这一步只是重新划分已有数字，**没有增加数字，也没有计算新的数值。**

所以，拆头以后：

- token 的数量没有减少。
- 每个头仍然包含全部 `T` 个 token
- 每个头中，**每个 token 的向量变短了**。
- 全部头加起来，数字的总数量没有变。

##### 3. 调整维度顺序，把头维移到序列维前面

调整维度顺序：

```
(batch, seq_len, h_heads, d_head) 
→ (batch, h_heads, seq_len, d_head)
```

这样排列，是为了方便后面**以每个头为单位，计算整段序列的注意力**。

调整后，Q、K、V 的形状都是：
$$
(B,H,T,D)
$$
对于每段文本的每个头，都有：

- 全部 `T` 个 token 在这个头中的 Q。
- 全部 `T` 个 token 在这个头中的 K。
- 全部 `T` 个 token 在这个头中的 V。

每个头使用自己的 Q、K、V 独立计算注意力。

##### 4. 对 Q、K 加入 RoPE 位置信息

**RoRE的核心是：根据token位置，调整它的Q、K向量，让后面的点积计算能够体现token之间的相对位置。**

根据每个 token 所处的位置，对它的 Q、K 做旋转调整，V 保持不变。这样，后面用 Q、K 计算匹配分数时，就能考虑位置关系。这一步不改变形状。

**1. 接收拆头后的 Q、K**

拆头之后，Q、K 的形状都是：
$$
(B,H,T,D)
$$
其中：

- B：这一批包含多少段文本。
- H：注意力头的数量。
- T：每段文本包含多少个 token。
- D：每个 token 在每个头中的特征维度。

也就是说，在每个注意力头里，**每个 token 都有一条长度为 D 的 Q 向量，以及一条长度为 D 的 K 向量。**

Q、K 来自对输入的线性投影，但**线性投影这个操作本身，并没有显式使用 token 的位置编号**。

RoPE 接下来要做的，就是把位置信息加入这些 Q、K 向量中。

注意：**它处理的是每个 token 自己的向量，此时还没有让不同 token 相互计算注意力。**

**2. 在每条向量内部，把数字两两分组**

先只看某个 token 在某个头中的 Q 向量：
$$
q=[q_0,q_1,q_2,q_3,\ldots,q_{D-2},q_{D-1}]
$$
按照你这里的相邻维度配对方式，把它拆成：
$$
(q_0,q_1),\quad(q_2,q_3),\quad\ldots,\quad(q_{D-2},q_{D-1})
$$
一共得到：
$$
\frac D2
$$
组，每组有两个数字，因此要求 **D 为偶数**。

**每一组包含两个特征分量，后面分别对每组进行旋转。**

这里分组的是：

- 同一个 token 的向量内部的数字。
- 不是把两个 token 分成一组。
- 也不是把一个 Q 分量和一个 K 分量配成一组。

因为每组需要两个数字，所以每个头的维度 D 必须是偶数。

K 向量也按同样的方式分组。

**3. 根据“token 的位置”和“第几组”，确定旋转角度**

`p` 表示哪个位置的 token:
$$
p=0,1,2,\ldots,T-1
$$
`i` 表示这个 token 的向量内部第几组数字，每组包含两个分量:
$$
i=0,1,2,\ldots,\frac D2-1
$$
因此，**确定了 p 和 i，就确定了“哪个 token 的哪一组数字”。**

K 向量也按同样的规则处理。

ω_i 表示：第 i 组每跨一个位置，角度增加多少。

公式：
$$
\omega_i=\theta^{-\frac{2i}{D}}
$$
这里：

- θ：预先设定的 RoPE 基数。
- D：每个头的向量宽度。
- i：当前是第几组数字。

当 θ 和 D 已经确定后，**代入不同的组编号 i，就会算出不同组各自的 omega_i**。

在通常的 θ>1 设定下，组编号$i 越大，算出的 omega_i越小。因此，有些组的角度随位置变化得较快，有些组变化得较慢。

然后，计算第 p个位置、第 i 组使用的旋转角度为：
$$
\alpha_{p,i}=p\cdot\omega_i
$$
这里：

- p：这个 token 在序列中的位置。
- omega_i：第 i 组预先设定的旋转频率，也就是**位置每前进一步，这一组的角度增加多少**。

因此，角度由两个因素共同决定：

**同一组，token 的位置不同，旋转角度就随之变化。**

**同一个 token，不同组使用不同频率，因此旋转角度也可以不同。**

不同组有的转得快，有的转得慢，让向量中的不同部分以不同的变化速度表达位置。

这些频率通常由预设公式确定，不需要为每个位置单独学习一条向量。

**4. 使用旋转公式，更新每组中的两个数字**

将某一组原来的两个数字记为：
$$
(a,b)
$$
可以把它看成二维平面中的一个向量：a 是横向分量，b 是纵向分量。

将这个向量旋转角度 α，得到：
$$
a'=a\cos\alpha-b\sin\alpha\\b'=a\sin\alpha+b\cos\alpha
$$
原来的两个数字 (a,b)，就变成了新的两个数字 (a',b')。

所以，**“旋转”在代码里，就是用这两条公式重新计算这一组数字。**

它有两个关键特点：

- **数值通常会改变**，因为向量的方向改变了。

- **这一对数字的平方和不变**，即 

- $$
  a'^2+b'^2=a^2+b^2
  $$

  所以旋转保持长度。

**5. 将各组旋转后的结果放回对应位置**

Q 向量中的各组完成旋转后，重新组成长度为 D 的向量：
$$
\widetilde q = [\widetilde q_0,\widetilde q_1,\ldots,\widetilde q_{D-1}]
$$
K 同样得到：
$$
\widetilde k = [\widetilde k_0,\widetilde k_1,\ldots,\widetilde k_{D-1}]
$$
对所有文本、所有注意力头、所有 token 完成处理后，得到：
$$
\widetilde Q,\widetilde K
$$
每组仍然是两个数字，每条向量仍然有 D 个分量，token 数量和排列顺序也没有改变。因此：
$$
Q,K,V∈R^{B\times H \times T \times D}
$$
**6. 将旋转后的 Q、K 交给后续的注意力分数计算**

对所有维度对完成旋转后，得到：
$$
\widetilde Q,\widetilde K,V \in\mathbb R^{B\times H\times T\times D}
$$
其中，Q、K 的数值经过位置相关的调整，V 保持不变。这里为什么能够体现相对位置？

对于同一组特征，两个向量分别旋转了：
$$
p\omega_i \qquad\text{和}\qquad s\omega_i
$$
它们的旋转角度之差为：
$$
s\omega_i-p\omega_i=(s-p)\omega_i
$$
其中，s-p 就是两个 token 的相对位置差。它既包含相隔多少个位置，也包含前后方向：

- s>p：Key 在 Query 后面。
- s：Key 在 Query 前面。
- s=p：两者来自同一个位置。

因此，**两个位置之间的关系，被转换成了两组向量之间额外的旋转差。**

**二维向量的点积与它们之间的方向关系有关，因此，旋转后的点积会同时受到原有内容和相对位置的影响。** 这并不保证距离越近，注意力分数就越高。

到这里，RoPE 处理完成。接下来使用 
$$
\widetilde Q、\widetilde K
$$
计算匹配分数。

##### 5. 用旋转后的 Q 和 K 计算匹配分数

**1. 明确要计算哪些位置之间的匹配**

因为每段文本的每个头，都要计算保存“每个位置对所有位置的匹配分数”。

在每个头内部，拿每个位置的  \(\widetilde Q\)，与所有位置的  \(\widetilde K\)，分别计算点积。

**点积就是：将两条向量中对应的分量相乘，再把乘积加起来，得到一个匹配分数。**

因此，一个位置的 Q 与一个位置的 K 做点积，得到一个分数；所有位置两两计算，就得到一个**T*T**的分数矩阵。

**2. 转置 K 的最后两个维度**

旋转后的 Q、K 形状都是：
$$
(B,H,T,D)
$$
为了通过矩阵乘法一次算出所有位置之间的点积，只交换
$$
\widetilde K
$$
 的最后两个维度：
$$
\widetilde K^\top: \quad (B,H,T,D)\longrightarrow(B,H,D,T)
$$
这里的转置只是调整张量的维度排列，不会改变 token 在序列中的先后顺序。

即：
$$
 (B,H,T,D) \longrightarrow (B,H,D,T) 
$$
矩阵乘法的最后两个维度变化为：
$$
(T,D)\times(D,T)\longrightarrow(T,T)
$$
**3. 进行矩阵乘法，得到未缩放的分数**

记未缩放的分数为 M：
$$
M=\widetilde Q\widetilde K^\top
$$
先看最后两个维度：
$$
(T,D)\times(D,T)\longrightarrow(T,T)
$$
也就是：

$$
(\text{seq\_len},d_{\text{head}})\times(d_{\text{head}},\text{seq\_len})
\longrightarrow(\text{seq\_len},\text{seq\_len})
$$



前面的 B、H 保留，表示每段文本、每个头分别计算。因此：
$$
M\in\mathbb R^{B\times H\times T\times T}
$$
两个 T 分别表示：

- **第一个 T 来自 Q**：有多少个位置在寻找信息，对应矩阵的行。
- **第二个 T 来自 K**：每个位置要与多少个位置进行匹配，对应矩阵的列。

**D 不再出现在结果形状中，是因为每次点积都把 $D$ 个分量的乘积加起来，汇总成一个分数。**

具体来说，第 p 行、第 s 列保存的就是：
$$
M_{p,s} = \sum_{j=0}^{D-1} \widetilde q_{p,j}\widetilde k_{s,j}
$$
这里省略了 batch 和 head 下标，表示某段文本、某个头内部的计算。

| 符号 | 含义                           |
| ---- | ------------------------------ |
| $p$  | 选中了哪个位置的 Q             |
| $s$  | 选中了哪个位置的 K             |
| $j$  | 正在相乘的是向量里的第几个数字 |

**4. 将分数除以 $\sqrt D$，调整尺度**

因为：
$$
D=d_{\text{head}}
$$
所以缩放后的分数为：
$$
S=\frac{M}{\sqrt D} = \frac{\widetilde Q\widetilde K^\top}{\sqrt{d_{\text{head}}}}
$$
这样可以减轻特征维度增大时，点积分数尺度随之增大的影响，降低后续 softmax 过于集中的倾向。

**这里只进行一次缩放。** 缩放只改变分数数值，不改变形状：
$$
S\in\mathbb R^{B\times H\times T\times T}
$$
接下来，再对 S 进行因果遮罩和 softmax。

##### **6. 用因果掩码屏蔽未来位置**

目前已经计算出所有位置之间的分数，但当前位置只允许参考自己和之前的位置。

对于 Query 位置 \(i\)：

- Key 位置 \(j\leq i\)：保留分数。
- Key 位置 \(j>i\)：将分数设为负无穷。

记屏蔽后的分数为 \(\bar S\)：
$$
\bar S_{i,j}= \begin{cases} S_{i,j}, & j\leq i\\ -\infty, & j>i \end{cases}
$$
这里省略了 batch 和 head 下标。相同的因果规则作用于每个样本、每个头。

**掩码修改的是匹配分数，不直接修改 Q、K、V。** 对角线保留，因此每个位置至少可以关注自己。

形状仍然是：
$$
(B,H,T,T)
$$

##### **7. 沿 Key 位置维度做 Softmax，得到注意力权重**

**这一步的作用是：把每个 Query 位置对各个 Key 位置的匹配分数，转换成一组总和为 1 的注意力权重，为下一步加权汇总 V 做准备。**

**第 1 步：接收经过因果掩码处理的匹配分数**

前面已经完成了 Q、K 的点积、缩放和因果掩码，得到屏蔽后的分数张量：
$$
\bar S\in\mathbb R^{B\times H\times T\times T}
$$
其中：

- 第一个 `T` 对应 Query 位置，表示哪个位置正在寻找信息。
- 第二个 `T` 对应 Key 位置，表示它正在与哪个位置匹配。

对于某个 Query 位置，它与自己及之前位置的匹配分数被保留，与未来位置的匹配分数已经被设为负无穷。

此时得到的仍然是匹配分数，接下来要把它们转换成混合 V 时使用的权重。

**第 2 步：固定一个 Query 位置，取出它对应的一整行分数**

固定一个样本、一个注意力头，以及一个 Query 位置 p。

这个位置对应的一整行分数为：
$$
\bar S_{p,0},\ \bar S_{p,1},\ \ldots,\ \bar S_{p,T-1}
$$
这里省略了 batch 和 head 下标。

这一行包含 T 个分数，分别表示 Query 位置p 与各个 Key 位置的匹配情况。

**Softmax 就在这一行内部进行，决定当前 Query 应当怎样在各个 Key 位置之间分配权重。**

这就是“沿 Key 位置维度做 Softmax”的含义，也就是沿张量的最后一维处理。

**第 3 步：让这一行的所有分数减去这一行的最大值**

先找出当前行的最大分数：
$$
m_p = \max_{0 \le k < T} \bar{S}_{p,k}
$$
其中，k 用来遍历这一行的所有 Key 位置。

然后，让这一行的每个分数都减去 m_p。对于 Key 位置 s，调整后的分数为：
$$
\bar S_{p,s}-m_p
$$
这样处理后，这一行最大的分数变成 0，其余分数都不大于 0；被屏蔽位置的分数仍然是负无穷。

**这一步是为了避免后面的指数运算产生过大的数值。**

同一行所有分数都减去相同的值，不会改变最终的 Softmax 权重：后面的指数结果会同时乘上相同的因子，这个因子在除以总和时会相互抵消。

**第 4 步：对调整后的每个分数做指数运算**

对于这一行中的每个 Key 位置 s，计算：
$$
E_{p,s}=\exp(\bar S_{p,s}-m_p)
$$
这里的 E_{p,s} 表示指数运算后的中间结果，还需要在下一步转换成权重。

指数运算有以下作用：

- 有限的分数经过指数运算后，在数学上得到正数。

- 同一行中，原来的分数越大，指数运算后的结果也越大。

- 被屏蔽的未来位置满足 

- $$
  \exp(-\infty)=0
  $$

  

- 因此对应结果为 0。

这样，就得到了一行非负的中间结果，同时保留了分数的大小关系。

**第 5 步：求出这一行的总和，再把每个结果除以这个总和**

先把这一行的指数结果全部加起来：
$$
\sum_{k=0}^{T-1}E_{p,k}
$$
然后，让每个位置的指数结果除以这个总和，得到注意力权重：
$$
A_{p,s}=\frac{E_{p,s}}{\sum_{k=0}^{T-1}E_{p,k}}
$$
**分子是当前 Key 位置的指数结果，分母是当前这一行所有 Key 位置的指数结果之和。**

因此，每个权重表示该位置的指数结果在这一行总量中所占的比例。

处理后：

- 每个权重都不小于 0。
- 同一行内，分数越高，对应的权重越大。
- 每行权重之和为 1，实际计算中可能有微小浮点误差。
- 被屏蔽的未来位置权重为 0。

把指数运算展开，就得到完整的稳定 Softmax 公式：
$$
A_{p,s}= \frac{\exp(\bar S_{p,s}-m_p)} {\sum_{k=0}^{T-1}\exp(\bar S_{p,k}-m_p)}
$$
**第 6 步：对所有行完成相同处理，输出注意力权重**

对每个样本、每个注意力头、每个 Query 位置，都分别完成上述处理。

每一行都使用自己的最大值和自己的指数结果总和，因此每个 Query 位置都有独立的一组权重。

**“每一行单独处理”描述的是计算范围；实际计算时，可以同时处理很多行。**

处理前，每一行有 $T$ 个匹配分数；处理后，每一行仍然有 $T$ 个注意力权重。因此，张量形状保持不变：
$$
\bar S:\ (B,H,T,T) \quad\longrightarrow\quad A:\ (B,H,T,T)
$$
其中，$A_{p,s}$ 表示：**在下一步为 Query 位置 $p$ 汇总内容时，Key / Value 位置 $s$ 的 V 向量应该乘多大的系数。**

接下来，第 8 部分就使用这些权重，对各个位置的 V 进行加权求和。

##### **8. 根据注意力权重混合 V**

**第 8 部分做的事情是：按照第 7 部分得到的权重，把各个位置的 V 向量加权汇总，为当前 token 一条包含上下文信息的新向量。**

**第 1 步：接收注意力权重 A 和内容向量 V**

第 7 部分已经通过 Softmax 得到注意力权重：
$$
A\in\mathbb R^{B\times H\times T\times T}
$$
前面通过线性投影、拆头和维度调整，已经得到 V：
$$
V\in\mathbb R^{B\times H\times T\times D}
$$
两者在这一步的分工是：

- **A 提供权重：**规定当前 Query 在汇总内容时，各个位置的 V 分别应该乘多大的系数。
- **V 提供内容：**每个位置都有一条包含 D 个分量的 V 向量，供后续加权汇总。

**一个权重是一个数字，一条 V 是包含 D 个数字的向量。**

**第 2 步：固定一个 Query 位置，取出它对应的一行权重**

固定一个样本、一个注意力头，以及一个 Query 位置 p。下面省略 batch 和 head 下标，位置编号统一从 0 到 T-1。

Query 位置 p 对应的一行权重为：
$$
A_{p,0},\ A_{p,1},\ \ldots,\ A_{p,T-1}
$$
这个头中，各个位置的 V 向量为：
$$
V_0,\ V_1,\ \ldots,\ V_{T-1}
$$
每个权重与同一来源位置的 V 对应：权重 A_{p,s} 用来乘位置s的 V_s。

这里：

- p：正在汇总信息的 Query 位置。
- s：提供内容的来源位置。

**前面与位置 s 的 K 匹配得到的权重，现在用来加权同一位置的 V。**

**第 3 步：把每个权重乘到对应 V 向量的全部分量上**

先看任意一个来源位置 s，它的 V 向量为：
$$
V_s=[v_{s,0},v_{s,1},\ldots,v_{s,D-1}]
$$
用对应的权重 A_{p,s} 乘它：
$$
A_{p,s}V_s = [A_{p,s}v_{s,0},\ A_{p,s}v_{s,1},\ \ldots,\ A_{p,s}v_{s,D-1}]
$$
**同一个权重，会分别乘到这条 V 的每个分量上。**

乘完以后，这条向量仍然包含 D 个数字，只是各个数字按照这个权重进行了缩放。

对全部来源位置完成这一步，就得到 **T 条经过加权的 D 维向量**。

未来位置的权重为 0，因此这些位置的 V 乘以权重后变成零向量，不会贡献到后面的求和结果中。

**第 4 步：将加权后的向量逐分量相加，得到当前 Query 的输出**

把这 T 条加权后的向量汇总起来：
$$
O_p =A_{p,0}V_0+A_{p,1}V_1+\cdots+A_{p,T-1}V_{T-1}
$$
也可以写成求和形式：
$$
O_p=\sum_{s=0}^{T-1}A_{p,s}V_s
$$
这里的“相加”按照分量位置分别进行：

- 所有加权向量的第 1 个分量相加，得到输出的第 1 个分量。
- 所有加权向量的第 2 个分量相加，得到输出的第 2 个分量。
- 依此类推，直到第 D 个分量。

**每个分量位置各自得到一个求和结果，一共得到 D 个结果，因此最终组成一条 D 维向量。**

这条向量就是 Query 位置 p 的输出 O_p，其中汇总了这个头从当前位置及之前位置提取的内容。

**第 5 步：对所有 Query 位置完成相同处理**

处理下一个 Query 位置时，使用它自己对应的那一行权重，再对这个头中的 V 向量进行加权汇总。

在同一个样本、同一个头内：

- 各个 Query 位置使用同一组 V 向量。
- 各个 Query 位置拥有各自的一行注意力权重。
- 权重分配可以不同，因此汇总出的内容也可以不同。

一共有 T 个 Query 位置，每个位置得到一条 D 维输出向量，所以这个头的输出形状为：**(T,D)**

所有 Query 位置的计算，可以通过一次矩阵乘法完成：**O=AV**

只看一个样本、一个头内部的形状：
$$
(T,T)\times(T,D)\longrightarrow(T,D)
$$
**A 的每一行提供一组权重，用它们对 V 的各行进行加权求和，得到 O 的一行。**

其中：

- **被求和的 T** 对应提供内容的来源位置，这些位置的内容被加权汇总。
- **保留下来的 T** 对应各个 Query 位置，每个位置保留自己的输出。
- **保留下来的 D** 是每条输出向量的宽度。

**第 6 步：对所有样本、所有注意力头完成计算，输出结果**

每个样本、每个注意力头，都使用各自的 A 和 V 完成上述计算。前面的 B、H 维度保留，因此完整的形状变化为：
$$
(B,H,T,T)\times(B,H,T,D)\longrightarrow(B,H,T,D)
$$
最终得到：
$$
O\in\mathbb R^{B\times H\times T\times D}
$$
此时，每个 token 在每个注意力头中，都有一条 D 维的上下文向量。

接下来，第 9 部分会把同一个 token 在不同头中的这些向量拼接起来，恢复为一条 d_model 维向量。

总之：

**Q、K 决定怎样分配权重，V 提供被混合的内容。** 完成这一步后，每个位置都得到一条由本头汇总出的上下文向量。

##### **9. 将多个头的结果拼接回来**

先调整维度顺序，让同一个 token 在各个头中的结果排列到一起：
$$
(B,H,T,D) \longrightarrow (B,T,H,D) 
$$
然后合并最后两个维度：
$$
 (B,T,H,D) \longrightarrow (B,T,HD) = (B,T,d_{\text{model}}) 
$$
每个头贡献 \(D\) 个特征，\(H\) 个头合起来恢复为 `d_model` 个特征。

**这里是拼接，不是相加或取平均。** 各个头的结果依次保留在同一条向量中。

这一步只调整排列和形状，不通过运算产生新的特征值。

记拼接后的结果为：
$$
O_{\text{concat}} \in\mathbb{R}^{B\times T\times d_{\text{model}}}
$$

##### **10. 通过输出投影，组合不同头的信息**

将拼接后的向量再经过一次线性变换：
$$
 \text{attention\_output} = O_{\text{concat}}W_O^\top 
$$
其中：
$$
W_O\in\mathbb{R}^{d_{\text{model}}\times d_{\text{model}}}
$$
这次变换对每个 token 单独进行。输出向量中的每个分量，都可以由拼接向量中的多个分量加权组合，因此能够综合不同头提供的信息。

两步的区别是：

- **拼接：**将各个头的结果放入同一条向量。
- **输出投影：**学习怎样组合这些特征。

输出投影混合的是同一个 token 的特征，不会再次直接混合不同位置。

最终得到：
$$
\text{attention\_output} \in\mathbb{R}^{B\times T\times d_{\text{model}}}
$$
这就是
$$
\operatorname{Attention}(z)
$$
的输出。

##### 11. 将 Attention 输出加回归一化前的原输入

回到 TransformerBlock，将 Attention 输出与之前保留的原始 `x` 逐元素相加：
$$
x_{\text{updated}} = x+\text{attention\_output}
$$
把前面的归一化和注意力计算展开，就是：
$$
x_{\text{updated}} = x+\operatorname{Attention} \bigl(\operatorname{RMSNorm}_1(x)\bigr)
$$
**Attention 使用归一化后的表示，残差加回的是归一化之前的 `x`。**

两者形状相同，因此相加发生在同一个样本、同一个 token、同一个特征位置上。

原有表示加上 Attention 根据上下文计算出的更新，得到新的隐藏状态。输出形状保持为：
$$
(B,T,d_{\text{model}})
$$
至此，完成了注意力子层及其残差连接。

随后进入前馈子层：保留这个更新后的状态，另一条路径经过独立的第二个 RMSNorm 和 FFN，再完成第二次残差相加：
$$
x_{\text{out}} = x_{\text{updated}} + \operatorname{FFN} \bigl(\operatorname{RMSNorm}_2(x_{\text{updated}})\bigr)
$$
这里的 
$$
\operatorname{RMSNorm}_1
$$
和 
$$
\operatorname{RMSNorm}_2
$$
 是两个独立的归一化模块，分别位于 Attention 和 FFN 之前，这就是这个 TransformerBlock 的 **pre-norm** 结构。

### 6. TransformerBlock骨架: SwiGLU（前馈子层）

**SwiGLU 的作用是：对每个 token 自己的特征向量进行非线性加工，再把加工结果加回原向量。**

注意力子层及其残差相加完成后，输入记为：
$$
x_{\text{updated}}\in\mathbb{R}^{B\times T\times d_{\text{model}}}
$$
其中：

- B：这一批有多少段文本。
- T：每段文本有多少个 token。
- d_model：每个 token 的向量包含多少个特征。

**前馈子层不会再次直接混合不同位置的信息。** 它逐位置处理向量，所有位置使用同一套权重。

以下按照默认的 **pre-norm + SwiGLU** 路径说明。

##### 第 1 步：保留输入，用于最后的残差相加

先保留进入前馈子层FFN的原始输入：
$$
\text{residual}=x_{\text{updated}}
$$
后续归一化和 SwiGLU 计算在另一条分支中进行。

**此时只是保留残差，尚未相加。** 最后加回的是归一化之前的 
$$
x_{\text{updated}}
$$
。

------

##### 第 2 步：通过 RMSNorm₂ 进行归一化

将输入送入第二个 RMSNorm：
$$
z=\operatorname{RMSNorm}_2(x_{\text{updated}})
$$
RMSNorm 对每个 token 的向量单独进行归一化，只沿最后一维 d_model 计算，不混合不同 token。

归一化后形状不变：
$$
z\in\mathbb{R}^{B\times T\times d_{\text{model}}}
$$

------

##### 第 3 步：通过两次线性映射，产生两条分支

将同一个 z 分别送入 `w1` 和 `w3`：
$$
u=zW_1^\top\\v=zW_3^\top
$$
两组权重相互独立，形状都是：
$$
W_1,W_3\in\mathbb{R}^{d_{\text{ff}}\times d_{\text{model}}}
$$
因此，两条分支都会把每个 token 的向量从 d_model 维映射到 d_ff 维：
$$
u,v\in\mathbb{R}^{B\times T\times d_{\text{ff}}}
$$
两条分支的作用分别是：

- **u：门控分支**，后续用于调节中间特征。
- **v：内容分支**，提供被调节的中间特征。

d_ff 通常大于 d_model，让模型能在更宽的中间空间中加工特征。**这里是扩展特征维度，不是拆分注意力头。**

------

##### 第 4 步：对门控分支应用 SiLU

只对门控分支 u 应用 SiLU：
$$
g=\operatorname{SiLU}(u)
$$
SiLU 的计算公式为：
$$
\operatorname{SiLU}(u)=u\odot\sigma(u)
$$
其中：
$$
\sigma(u)=\frac{1}{1+e^{-u}}
$$
以上运算对向量中的每个元素分别进行，因此形状不变：
$$
g\in\mathbb{R}^{B\times T\times d_{\text{ff}}}
$$
**SiLU 为这一分支引入非线性，得到后续调节内容分支的一组数值。**

这些数值不是只有 0 和 1 的开关，也不限定在 0 到 1 之间；它们可以缩小、放大或改变对应内容的符号。

------

##### 第 5 步：两条分支逐元素相乘

将门控结果 g 与内容分支 v 相乘：
$$
h=g\odot v
$$
即：
$$
h=\operatorname{SiLU}(zW_1^\top)\odot(zW_3^\top)
$$
这里的 点积表示**对应位置上的元素分别相乘**：
$$
h_{b,t,j}=g_{b,t,j}\,v_{b,t,j}
$$
也就是说，对于某个 token，第 j 个门控数值只调节它自己第 j 个内容特征。

两条分支的形状完全相同，相乘后仍为：
$$
h\in\mathbb{R}^{B\times T\times d_{\text{ff}}}
$$
**这一步没有把不同 token 相乘，也没有把所有特征加成一个数，而是保留 d_ff 个经过调节的特征。**

------

##### 第 6 步：通过 W₂，映回模型宽度

将相乘结果送入 `w2`：
$$
\text{FFN}_{\text{output}}=hW_2^\top
$$
其中：
$$
W_2\in\mathbb{R}^{d_{\text{model}}\times d_{\text{ff}}}
$$
这次线性映射将同一 token 的中间特征重新组合，从 d_ff 维映回 d_model维：
$$
\text{ffn}_{\text{output}} \in\mathbb{R}^{B\times T\times d_{\text{model}}}
$$
因此，完整的 SwiGLU 公式为：
$$
\boxed{ \operatorname{SwiGLU}(z) = \left[ \operatorname{SiLU}(zW_1^\top) \odot (zW_3^\top) \right]W_2^\top }
$$
这里三次线性映射均按无 bias 的实现书写。

------

##### 第 7 步：与保留的输入进行残差相加

将 SwiGLU 输出与第 1 步保留的原始输入逐元素相加：
$$
x_{\text{out}} = x_{\text{updated}}+\text{ffn}_{\text{output}}
$$
两者都是 (B,T,d_model)，所以可以直接相加。

完整表达式为：
$$
\boxed{ x_{\text{out}} = x_{\text{updated}} + \operatorname{SwiGLU} \left( \operatorname{RMSNorm}_2(x_{\text{updated}}) \right) }
$$
**残差连接让模型在保留原有表示的基础上，加入前馈子层计算出的更新。**

最终形状仍为：
$$
x_{\text{out}}\in\mathbb{R}^{B\times T\times d_{\text{model}}}
$$


------

##### 第 8 步：将结果交给后续模块

到这里，一个 Transformer Block 的两次子层更新都已完成：
$$
x_{\text{updated}} = x+\operatorname{Attention}(\operatorname{RMSNorm}_1(x))$$x_{\text{out}} = x_{\text{updated}} + \operatorname{SwiGLU}(\operatorname{RMSNorm}_2(x_{\text{updated}}))
$$
如果后面还有 Block，就将 x_out 交给下一层。

如果这是最后一层 Block，则交给整网的 `ln_final`，再通过 `lm_head` 计算词表分数。

**`ln_final` 位于所有 Block 之后，不属于某个 Block 内部。**

------

##### 补充：切换为 SiLU-FFN 时有什么变化？

开启 `use_silu_ffn` 后，前馈内部改为：
$$
\operatorname{SiLUFFN}(z) = \operatorname{SiLU}(zW_1^\top)W_2^\top
$$
处理顺序是：

1. `w1` 将特征映射到中间宽度。
2. SiLU 进行非线性加工。
3. `w2` 将特征映回 d_model

它没有 `w3` 内容分支，也没有两条分支逐元素相乘。**前面的 RMSNorm 和后面的残差相加保持相同的处理顺序。**

### 7. 从 logits 到一次参数更新

**全部 Transformer Block 处理完成后，模型先把每个位置的隐藏向量转换成词表分数，再根据正确答案计算损失，最后通过反向传播和优化器更新参数。**

以下按默认保留 RMSNorm、`lm_head` 与 embedding 不共享权重的配置说明。

------

##### 第 1 步：对最后一层 Block 的输出进行归一化（即ln_final）

全部 Block 处理完成后，得到隐藏状态：
$$
x_L\in\mathbb{R}^{B\times T\times d_{\text{model}}}
$$
全部 Transformer Block 处理完成后，先对最后一层 Block 的输出应用 `ln_final`（RMSNorm），再通过 `lm_head` 得到 logits：
$$
z=\operatorname{RMSNorm}_{\text{final}}(x_L)
$$
它对每个 token 的向量单独进行归一化，所有位置使用这一层相同的可学习参数，形状不变：
$$
z\in\mathbb{R}^{B\times T\times d_{\text{model}}}
$$
**`ln_final` 位于所有 Block 之后，与各个 Block 内部的 `ln1`、`ln2` 参数独立。**

注：**`ln1`、`ln2` 是代码中两个归一化层的名字。当前的模型里，它们都是 RMSNorm。**

一个 Transformer Block 包含注意力和前馈两个子层，各自在处理输入前做一次归一化：

| 名字  | 所在位置       | 做什么                                         |
| ----- | -------------- | ---------------------------------------------- |
| `ln1` | Attention 之前 | 将输入归一化，再交给注意力子层                 |
| `ln2` | SwiGLU 之前    | 将注意力残差相加后的结果归一化，再交给前馈子层 |

------

##### 第 2 步：通过 lm_head，得到词表分数

将归一化后的隐藏向量送入 `lm_head`：
$$
\text{logits}=zW_{\text{head}}^\top
$$
其中，令 V=vocab\_size，则：
$$
W_{\text{head}}\in\mathbb{R}^{V\times d_{\text{model}}}
$$
`lm_head` 本质上就是一个 `Linear` 层，它将最后一维从 d_model 变成 vocab_size
$$
(B,T,dmodel)⟶(B,T,vocab_size)
$$
这次线性映射把每个位置的 d_model 维向量，转换成对词表中 V 个 token 的打分：
$$
\text{logits}\in\mathbb{R}^{B\times T\times V}
$$
具体来说：
$$
\text{logits}[b,t,:]
$$
表示第 b 段输入、第 t 个位置，对词表中所有 token 的**未归一化分数**。某个 token 的分数越高，模型越倾向于把它预测为下一个 token。

**训练时直接把 logits 交给交叉熵，不需要在模型的 `forward` 中先做 softmax。**

------

##### 第 3 步：将每个位置的预测与正确答案 y 对齐

取 batch 时，已经准备了：

- x：输入 token ID，形状为 (B,T)。
- y：每个位置对应的下一个 token ID，形状为 (B,T)。

同一个训练窗口中，y 比 x 向后错开一个 token。因此：
$$
\text{logits}[b,t,:] \quad\text{对应的正确答案是}\quad y[b,t]
$$
**位置 t 的任务是：根据截至当前位置的输入，预测下一个 token。**

这里有两个不同的作用：

- **因果掩码**：限制模型计算位置 $t$ 的表示时，只能使用当前位置及之前的信息。
- **目标 y**：告诉损失函数，这个位置应该预测哪个 token。

y 不作为输入送入模型，而是在计算损失时使用。

------

##### 第 4 步：摊平 batch 维和序列维

为了把所有位置统一交给交叉熵，将 logits 和 y分别变形：
$$
(B,T,V)\rightarrow(BT,V)\\(B,T)\rightarrow(BT,)
$$
变形后：

- logits 的每一行，保存一个位置对整个词表的分数。
- y 的对应元素，保存这一行的正确 token ID。

**摊平只改变数据的排列形状，不改变分数，也不打乱预测与答案的对应关系。**

现在共有 BT 个需要计算损失的位置。

------

##### 第 5 步：为每个位置计算交叉熵

对于其中一个位置，记它的词表分数为：
$$
o\in\mathbb{R}^{V}
$$
正确 token 的 ID 为 y。

交叉熵衡量的是：**模型给正确 token 分配的概率是否足够高。**

数学上可以写为：
$$
\ell=-\log\left(\operatorname{softmax}(o)_y\right)
$$
正确 token 的概率越大，这个位置的损失越小。

实际计算时，不必先显式生成 softmax 概率，而可以直接使用：
$$
\ell=-o_y+\log\sum_{v=0}^{V-1}e^{o_v}
$$
为了避免指数运算溢出，先减去该行最大值：
$$
m=\max_v o_v,\qquad \widetilde{o}_v=o_v-m
$$
再计算：
$$
\boxed{ \ell=-\widetilde{o}_y+ \log\sum_{v=0}^{V-1}e^{\widetilde{o}_v} }
$$
所有分数减去同一个数不会改变 softmax 概率，因此这种稳定写法与原公式等价。

------

### 第 6 步：对所有位置的损失取平均

每个位置都有一个损失，再对 $BT$ 个位置求平均：

$\boxed{ \text{loss} = \frac{1}{BT} \sum_{b=1}^{B}\sum_{t=1}^{T}\ell_{b,t} }$

最终得到一个**标量**，用于表示当前 batch 的平均预测损失。

按照你描述的训练脚本，如果损失出现 NaN 或 Inf，程序会报错，不继续更新参数。

------

### 第 7 步：通过反向传播计算参数梯度

调用：

```
loss.backward()
```

反向传播根据计算图，计算损失对各个可学习参数的梯度：

$\frac{\partial\text{loss}}{\partial p}$

梯度保存在对应参数的 `.grad` 中，涉及：

- `lm_head`。
- `ln_final`。
- 各层 Block 中的 Attention、SwiGLU 和 RMSNorm。
- `token_embeddings`。

**反向传播只计算梯度，此时参数还没有更新。**

对于不与输出层共享权重的 embedding，本次输入 $x$ 中出现的 token，其对应行会接收到查表路径传回的梯度；未出现的行，这条路径的梯度为零。

但**零梯度不一定意味着该行完全不变**：后续 AdamW 的历史动量或权重衰减仍可能使它变化。整个参数的 `.grad` 为 `None` 与参数中某些行的梯度为零，也不是一回事。

------

### 第 8 步：对梯度进行全局 L2 裁剪

在更新参数之前，先检查梯度的整体大小。

把所有有梯度的参数的梯度视作一条大向量，其全局 L2 范数为：

$G= \sqrt{ \sum_{\text{参数 }p} \sum_i \left(\frac{\partial\text{loss}}{\partial p_i}\right)^2 }$

设允许的最大范数为 $C=\text{max\_grad\_norm}$。

如果：

$G\le C$

则保持梯度不变。

如果：

$G>C$

则所有梯度乘以同一个缩放系数：

$\frac{C}{G+\varepsilon}$

**梯度裁剪缩小的是梯度，不是直接缩小参数。** 统一缩放可以保留整体梯度方向，同时限制其大小。

按照你的笔记，脚本默认阈值为 `1.0`，日志记录的是裁剪前的范数。

------

### 第 9 步：AdamW 根据梯度更新参数

调用：

```
optimizer.step()
```

这时才真正修改模型参数。

对参与更新的参数 $p$，AdamW 使用裁剪后的梯度 $g_s$，并维护两组历史统计量。这里用 $s$ 表示优化步数，避免与 token 位置 $t$ 混淆。

**① 更新一阶动量：记录梯度的滑动平均。**

$m_s=\beta_1m_{s-1}+(1-\beta_1)g_s$

**② 更新二阶动量：记录梯度平方的滑动平均。**

$v_s=\beta_2v_{s-1}+(1-\beta_2)g_s^2$

其中，平方按元素计算。

**③ 进行偏差修正。**

因为 $m$、$v$ 通常从零开始，训练初期需要修正：

$\widehat m_s=\frac{m_s}{1-\beta_1^s}, \qquad \widehat v_s=\frac{v_s}{1-\beta_2^s}$

**④ 应用权重衰减和 Adam 更新。**

标准形式可以写为：

$\boxed{ p\leftarrow (1-\eta_s\lambda)p - \eta_s \frac{\widehat m_s}{\sqrt{\widehat v_s}+\varepsilon} }$

其中：

- $\eta_s$：当前学习率，控制这一步的更新幅度。
- $\lambda$：权重衰减系数。
- $\varepsilon$：用于数值稳定的小常数。

**“解耦权重衰减”表示衰减直接作用于参数，不加入梯度的动量计算。**

同一个优化器可以管理 embedding、各层 Block 和 `lm_head`，但每个参数都有自己的动量状态。

------

### 第 10 步：进入下一次训练迭代

参数更新后，下一次前向传播会使用新的参数，包括更新后的 embedding 表、注意力权重和前馈权重。

为了把上面的计算放回完整训练循环，一次 iteration 的顺序是：

| 顺序 | 操作                    | 作用                              |
| ---- | ----------------------- | --------------------------------- |
| 1    | 设置当前学习率          | 决定本次参数更新使用的学习率      |
| 2    | 取得 $x,y$              | 准备输入和下一个 token 的正确答案 |
| 3    | `optimizer.zero_grad()` | 清除上一步留下的梯度              |
| 4    | `logits = model(x)`     | 计算每个位置的词表分数            |
| 5    | 计算交叉熵              | 得到标量 loss                     |
| 6    | `loss.backward()`       | 计算参数梯度                      |
| 7    | 梯度裁剪                | 限制全局梯度大小                  |
| 8    | `optimizer.step()`      | 更新模型参数                      |

其中，第 1 步的余弦学习率调度分为三段：

- **Warmup**：学习率从 0 线性升至 `max_lr`；没有 warmup 时，直接从 `max_lr` 开始。
- **余弦退火**：学习率逐渐降至 `min_lr`。
- **退火结束后**：保持 `min_lr`。

验证、日志记录和 checkpoint 保存按设定间隔执行。验证时不进行反向传播和优化器更新。
