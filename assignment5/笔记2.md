#### 1. 从预训练大模型到强化学习训练闭环

#### 1.1 大纲

核心：Policy 生成 → Reward 打分 → Advantage 比较 → Policy Gradient→ 更新**

整个过程可以分成两部分：

**生成阶段：Policy → Response**

**训练阶段：Response → 更新 Policy**

**闭环**：**生成 → 评价 → 比较 → 更新 → 再生成。**

**完整主线**

```
大规模文本
↓
Pretraining
↓
Base Model
↓
SFT
↓
SFT Model
↓
作为初始 Policy
↓
Prompt / State
↓
Policy 输出 Token 概率分布
↓
Decoding + Sampling
↓
不断生成 Token
↓
Rollout / Response
↓
Reward
↓
Baseline
↓
Advantage
↓
Policy Gradient Loss
↓
Backward
↓
Gradient
↓
Optimizer
↓
更新 Transformer 参数
↓
New Policy
↓
新的 Token 概率分布
↓
再次 Rollout
```

- 其中：
  - **Policy**：根据当前 State 产生下一 Token 的概率分布
  - **Decoding Strategy**：规定如何根据概率分布选择实际 Token
  - **Sampling / Selection**：真正选择一个 Token
  - **Rollout / Response**：Policy 连续生成 Token 后得到的一次完整输出
  - **Reward**：对 Response 进行评分
  - **Baseline + Advantage**：将当前表现与基准进行比较
  - **Policy Gradient + Backward + Optimizer**：根据 Advantage 更新模型参数
  - **Policy 更新后**：模型参数改变，下一轮 Token 概率分布随之改变

#### 1.2 第一阶段：学会生成

##### **1.21 大规模文本**→Pretraining**预训练**→**base model**

预训练的核心任务通常是：**根据前面的 Token，预测下一个 Token。**

通过大量这种训练，模型逐渐学会语言规律、知识和文本生成能力。

因此，此时的 **Base Model** 已经具备：

- 语言理解和生成能力
- 一定的世界知识
- 根据上下文预测下一个 Token 的能力

但是它仍然存在一个问题：**虽然会生成文本，但还不一定能够稳定地按照用户指令回答问题。**

因此需要进一步进行 **SFT**。

#### 1.3 第二阶段：学会按要求回答

##### **1.31 base model →SFT → SFT Model**

**SFT 核心**：**给模型提供标准回答示范，让模型学习应该怎样按照 Prompt 回答**

**SFT 数据**：**Prompt + 标准 Response**

**SFT过程**：SFT 使用**Prompt + 标准 Response**作为监督数据，教base model学会回答方式

```
Prompt+标准 Response
↓
模型逐 Token 预测标准 Response 中的下一个 Token
↓
预测结果与标准 Token 比较
↓
Cross Entropy Loss
↓
Backward
↓
Gradient
↓
Optimizer
↓
更新模型参数
```

**SFT结果**：**Base Model → SFT → SFT Model**

经过 SFT 后，模型从单纯**“会生成文本”**，进一步变成：**能够比较稳定地按照 Prompt 和任务格式生成 Response。**

但是，SFT 主要是在**模仿标准答案**。

它并没有直接解决：多个“都能回答”的 Response 中，哪个 Response 更好？

因此还可以继续进行强化学习后训练。

#### 1.4 第三阶段：学会偏向更好的回答

##### 1.41 SFT Model → 强化学习训练后→把模型视为 Policy

**强化学习阶段的目标：在模型已经会回答的基础上，让模型更倾向于生成符合奖励目标的高质量 Response。**

**SFT Model**→作为初始 **Policy**。**Policy 本质上仍然是这个语言模型本身**

区别只是：

在强化学习视角下，把语言模型看作一个：**根据当前 State 输出 Action 概率分布的策略。**

##### 1.42 Policy 生成 Response

**1.42.1Prompt 作为初始 State**

首先给模型一个 Prompt，作为初始State

在 LLM 强化学习中，State 可以理解为：**当前时刻模型已经看到的完整上下文**

也就是：

```text
刚开始：
State = Prompt

生成过程中：
State = Prompt + 已生成的 Response
```

**1.42.2 State → Policy → 下一 Token 概率分布**

当前 State 输入语言模型：

```text
State
↓
Transformer
↓
Logits
↓
Softmax
↓
下一 Token 概率分布
```

因此 Policy 做的事情是：

> **给定当前 State，为词表中的候选 Token 分配概率。**

例如从数学上写成：
$$
[
\pi_\theta(a_t\mid s_t)
]
$$
其中：

- $$
  s_t：当前 State\\
  a_t：当前 Action，也就是下一个 Token\\
  \pi_\theta：由模型参数 (\theta) 定义的 Policy\\
  \pi_\theta(a_t\mid s_t)：当前 State 下生成某个 Token 的概率
  $$

**1.42.3 Decoding Strategy：决定如何选择 Token**

模型已经得到了下一 Token 的概率分布，但仍然需要决定：**到底选择哪个 Token？**

这个过程由 **Decoding Strategy** 决定。

```text
Policy 输出概率分布
↓
Decoding Strategy
↓
Sampling / Selection
↓
实际 Token
```

Decoding Strategy 规定：**如何根据 Policy 输出的概率分布得到实际 Token。**

常见 Decoding Strategy 可以分成两类。

- **Greedy Decoding**: 每一步直接选择概率最高的 Token。

- **Sampling Decoding**: 不是直接选择概率最高的 Token，而是根据某个采样分布随机抽取 Token。

  - 常见方法包括：

    - Temperature Sampling

    - Top-k Sampling

    - Top-p Sampling

**1.42.4  Sampling：真正选择 Action**

在 Sampling Decoding 中，可以先调整采样分布，然后真正进行随机抽取。

**Sampling 把概率变成实际行为**

例如：

```text
原始概率分布
↓
Temperature / Top-k / Top-p
↓
调整后的采样分布
↓
Sampling
↓
一个实际 Token
```

因此：**Sampling = 根据一个概率分布，实际抽取一个 Token。**

此时这个 Token 就是强化学习中的：**Action**

**1.42.5 Token 加入上下文，形成新的 State**

生成一个 Token 后，将它加入已有上下文：

```text
旧 State + 新 Token
↓
新 State
```

新的 State 再次输入 Policy：

```text
新的State
↓
Policy
↓
新的下一个Token 概率分布
↓
Decoding Strategy
↓
Sampling / Selection
↓
下一个Token
↓
更新state
```

**1.42.6 连续 重复上述过程 → 完整 Response**

**一次 循环，只能得到一个 Token。**

因此要生成完整 Response，就需要不断重复上述过程：

```text
Prompt
↓
Sampling → Token₁
↓
Prompt + Token₁
↓
Sampling → Token₂
↓
Prompt + Token₁ + Token₂
↓
Sampling → Token₃
↓
...
↓
直到生成 EOS / 达到停止条件
↓
完整 Response
```

简化版过程：**Policy→连续 Action / Token→Rollout→完整 Response**

这一整段交互过程叫：**Trajectory / Rollout**

而 **Response** 是最终生成出来的 Token 序列。

因此在 LLM 强化学习中，可以理解为：**Rollout = Policy 完整生成一次 Response 的过程。**

##### 1.43 Reward：评价 Response

得到 Response 后，需要判断它表现得怎么样。

```text
Response
↓
Reward Function / Reward Model
↓
Reward
```

**Reward 的核心作用：给当前 Response 一个分数**

Reward 高，说明这个 Response 更符合训练目标。

Reward 低，说明这个 Response 较不符合训练目标。

但是，只知道 Reward 本身还不够。因为我们还需要知道：

> **这个 Reward 相对于正常水平，到底算好还是差？**

因此引入 **Baseline**。

##### 1.44 Baseline：提供比较基准

Baseline 可以理解为：**当前条件下的参考水平。**

Reward 告诉我们：这次得了多少分。

Baseline 告诉我们：通常大概应该达到什么水平。

然后通过比较 Reward 和 Baseline，判断这次 Response 的相对表现。

**不同算法中 Baseline 的来源不同：**

- **PPO**
  - 传统 PPO 中，Baseline 通常来自：**Critic / Value Function**
  - Critic 负责估计：当前 State 下，未来大概能够获得多少 Reward

- **GRPO**
  - GRPO 不依赖传统的独立 Critic。

对于同一个 Prompt：

```text
Prompt
↓
生成一组 Responses
↓
每个 Response 得到 Reward
↓
利用 group 内 Reward 构造baseline
```

最直观的简化理解是：

> **使用同一个 Prompt 下这一组 Response 的平均 Reward 作为 Baseline。**

##### 1.45 Advantage：判断当前 Response 相对表现

Reward 与 Baseline 比较后，可以得到 Advantage。

简化理解：
$$
Advantage \approx Reward-Baseline
$$
Advantage 的核心含义：**当前 Action / Response 相对于基准表现得有多好或多差。**

因此：

```text
Advantage > 0
↓
表现比基准更好
↓
应该鼓励

Advantage < 0
↓
表现比基准更差
↓
应该抑制
```

所以 Advantage 并不是梯度本身。

它主要告诉 Policy：**这次生成行为应该被鼓励还是抑制。**

##### 1.46 Policy Gradient：把 Advantage 转成模型更新信号

有了 Advantage 后，需要真正修改模型参数。

因此计算：

```text
Policy Gradient Loss
```

Policy Gradient 的核心思想是：

> **高 Advantage 的 Action，提高未来被 Policy 选择的概率。**

> **低 Advantage 的 Action，降低未来被 Policy 选择的概率。**

因此：

```text
Advantage
↓
Policy Gradient Loss
↓
Backward
↓
Gradient
```

Gradient 告诉模型：每一个参数应该朝哪个方向变化，以及变化多少。

##### 1.47 Optimizer 更新 Transformer 参数

得到 Gradient 后：

```text
Gradient
↓
Optimizer
↓
更新 Transformer 参数 θ
```

由于 Policy 就是由这些模型参数 (\theta) 定义的，因此：

```text
Transformer 参数改变
↓
Policy 改变
↓
下一 Token 概率分布改变
```

即：
$$
\pi_{\theta_{\text{old}}}
\rightarrow
\pi_{\theta_{\text{new}}}
$$
同样的 State 输入更新后的模型以后：各个 Token 的生成概率已经发生变化。

这就是强化学习真正“学到东西”的地方。

##### 1.48 强化学习完整闭环

模型更新以后，再重新进行生成：

```text
New Policy
↓
新的 Token 概率分布
↓
Decoding Strategy
↓
Sampling
↓
新的 Response
↓
新的 Reward
↓
新的 Baseline
↓
新的 Advantage
↓
新的 Policy Gradient Loss
↓
Backward
↓
Optimizer
↓
再次更新 Policy
```

不断重复：**生成 → 评价 → 比较 → 更新 → 再生成**，形成强化学习训练闭环。

### 2. Policy 在强化学习和 LLM 中的对应关系

##### 2.1 Policy 的一般定义

在**强化学习**中：**Policy（策略）= 在当前 State 下，对不同 Action 给出选择概率的规则**

即：**State → Policy → Action 概率分布**

在**大语言模型**中，RL 的这些概念可以直接对应过来。

| 概念                     | 强化学习中的含义                                | 大语言模型中的对应                              |
| ------------------------ | ----------------------------------------------- | ----------------------------------------------- |
| **State**                | Agent 当前所处的状态                            | **当前生成上下文：Prompt + 已生成的 Token**     |
| **Action**               | Agent 在当前 State 下采取的动作                 | **当前时间步生成的下一个 Token**                |
| **Policy**               | 给定 State 后，对各个 Action 定义概率分布的策略 | **由 LLM 参数化的下一哥 Token 条件概率分布**    |
| **Action Probability**   | 当前 State 下某个 Action 被选择的概率           | **某个候选 Token 的生成概率**                   |
| **Trajectory / Rollout** | 一系列 State–Action 交互形成的完整轨迹          | **一次完整的生成过程；简化理解为完整 Response** |

具体来说，在 LLM 强化学习中：

- **State（状态）**：当前生成上下文，即 `Prompt + 已生成的 Token 序列`
- **Action（动作）**：在当前时间步选择的下一个 Token
- **Policy（策略）**：由当前语言模型参数定义的条件概率分布，用于描述在给定 State 下各个候选 Token 被选择的概率
- **Policy Output（策略输出）**：给定当前 State 后，模型对词表中所有候选 Token 产生的下一 Token 概率分布

更标准地写成：\[ \pi_\theta(a_t \mid s_t) \]

其中：

- \(s_t\)：当前 State
- \(a_t\)：当前 Action，也就是下一个 Token
- \(\pi_\theta\)：由参数 \(\theta\) 定义的 Policy
- \(\pi_\theta(a_t \mid s_t)\)：在当前上下文下生成某个 Token 的概率

对应到 LLM：

```
Prompt + 已生成 Token
        ↓
   State s_t
        ↓
  Policy πθ（LLM）
        ↓
下一 Token 概率分布
        ↓
    Sampling
        ↓
 Action a_t
```

一句正式总结可以写成：

> **在 LLM 强化学习中，语言模型参数化了一个 Policy \(\pi_\theta\)，该 Policy 根据当前上下文 State \(s_t\)，为词表中的候选 Token 定义下一步 Action \(a_t\) 的条件概率分布。**

### 3. Decoding Strategy 与 Sampling

#### 3.1 Decoding Strategy

**Decoding Strategy = 规定如何根据模型输出的概率分布选择实际 Token。**

**Decoding**主要有两类：

 	1. Greedy Decoding：每一步直接选择概率最高的 Token
 	2. Sampling Decoding：不直接选择概率最高的 Token，而是按照某个处理后的概率分布随机抽取 Token

常见 Sampling 方法

- Temperature Sampling：原始概率分布→Temperature 调整分布→Sampling
  - 控制概率分布的尖锐程度和随机性
- Top-k Sampling：原始概率分布→只保留概率最高的 k 个 Token→重新归一化→Sampling
  - 限制 Sampling 只能从前 k 个候选中选择
- Top-p Sampling：原始概率分布→保留累计概率达到 p 的候选 Token→重新归一化→ Sampling
  - 动态限制 Sampling 的候选集合

它们的作用都是：**调整采样分布**，因此**Temperature / Top-k / Top-p** 就是 Sampling Decoding 中调整概率分布的具体策略

因此Policy、Decoding、Sampling clas三者的关系是：

```text
当前 State
↓
Policy
↓
原始 Token 概率分布
↓
Decoding Strategy
↓
可选：Temperature / Top-k / Top-p 等调整
↓
Sampling / Selection
↓
实际 Token
```

其中：

> **Decoding Strategy 是上层规则。**

> **Sampling 是实际选择 Token 的动作。**

> **Temperature / Top-k / Top-p 是 Sampling Decoding 中常见的概率分布调整策略。**
