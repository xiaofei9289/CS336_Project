# 1. 强化学习训练 Policy 的整体框架

## 1.1 最核心的训练闭环

强化学习训练 Policy，本质上就是：

```
Policy
↓
Sampling
↓
Action / Response
↓
Reward
↓
判断行为表现
↓
Policy Gradient
↓
Backward
↓
Optimizer
↓
更新 Policy
↓
再次 Sampling
```

对于大语言模型：

```
Prompt
↓
Policy
↓
根据概率分布 Sampling
↓
生成 Response
↓
Reward Function 打分
↓
判断 Response 表现
↓
根据表现更新 Policy
↓
下一轮重新生成 Response
```

核心可以概括为：

> **生成 → 评价 → 更新 → 再生成**

## 1.2 强化学习训练主要解决两个问题

整个知识体系可以拆成两条主线：

```
                     强化学习训练 Policy
                            │
              ┌─────────────┴─────────────┐
              │                           │
              ↓                           ↓
        如何判断行为好坏？          如何稳定更新 Policy？
              │                           │
           Reward                  Policy Gradient
              │                           │
          Baseline                   Vanilla PG
              │                           │
          Advantage                     TRPO
              │                           │
      ┌───────┴────────┐                 PPO
      │                │
经典 PPO            GRPO
Critic + GAE     Group Relative
      │                │
      └───────┬────────┘
              ↓
          Advantage
```

### 第一条线：行为到底好不好？

```
Reward
↓
Baseline
↓
Advantage
```

### 第二条线：知道行为好坏以后，怎么稳定更新 Policy？

```
Policy Gradient
↓
Vanilla Policy Gradient
↓
TRPO
↓
PPO
```

而：**经典 PPO** 和 **GRPO**

一个重要区别在于：**Advantage 怎么得到？**

# 2. Reward、Baseline 与 Advantage

## 2.1 Reward：给行为打分

Policy 生成 Action / Response 以后，需要知道：

> **这个行为到底表现怎么样？**

因此需要：**Reward**

Reward 最直接解决：

> **这个行为得了多少分？**

对于大语言模型：

```
Prompt
↓
Response
↓
Reward Function
↓
Reward
```

## 2.2 Reward 本身可以作为学习信号

最基础的 Policy Gradient 中，可以直接使用 Reward / Return 作为学习信号。

Reward / Return 可以 告诉 Policy，哪些行为带来了更高回报

但是直接使用 Reward / Return 往往存在一个问题：

```
不同采样结果波动较大
↓
Policy Gradient 方差较大
↓
训练可能不够稳定
```

而且仅看一个 Reward 数值，也不容易直观判断：

> **这个结果到底比当前情况下的正常水平好多少？**

因此通常会引入：**Baseline**

## 2.3 Baseline：建立参考水平

Baseline 可以理解为：**在当前情况下，正常表现大概是什么水平？**

然后：相对表现(advantage) = 实际表现(reward/return) - 正常水平(Baseline)

于是得到：Advantage，即**相对表现**

```
Reward / Return
↓
与 Baseline 比较
↓
Advantage
```

Baseline 的重要作用之一是：**1. 降低 Policy Gradient 的方差**；**2. 把绝对得分转化为相对表现**

## 2.4 Advantage：这个行为值得鼓励吗？

Advantage = 实际表现 - 正常水平

Advantage > 0 → 这个行为比正常水平好 → 应该提高这个行为的概率

Advantage < 0 → 这个行为比正常水平差 → 应该降低这个行为的概率

因此：**Reward 更像绝对表现；Advantage 更像相对表现。**

Advantage 真正回答的问题是：**这个行为到底应该被鼓励还是抑制？**

## 2.5 Reward、Baseline、Advantage 的关系

整体关系：

```
Action / Response
↓
Reward
↓
和 Baseline 比较
↓
Advantage
↓
判断这个行为：应该增加概率/还是降低概率
```

注意：

> **Baseline 不是 Policy Gradient 必须存在的前提，而是为了得到更稳定、更有意义的相对学习信号而经常引入。**

# 3. Policy Gradient 基础

## 3.1 Policy Gradient 是什么？

现在已经知道：

```
Advantage > 0 → 这个行为应该被鼓励
Advantage < 0 → 这个行为应该被抑制
```

但是还需要真正修改模型参数。这就是：Policy Gradient

Policy Gradient 的核心思想：**根据行为的表现，修改 Policy 对这些行为的概率。**

## 3.2 Advantage 如何影响 Policy

核心关系：

```
Advantage > 0 → 提高该 Action / Token 的概率
Advantage < 0 → 降低该 Action / Token 的概率
```

所以可以理解为：

> **Advantage 决定“希望往哪个方向改”，Policy Gradient 把这个信号转化成参数梯度。**

## 3.3 从 Policy Gradient 到参数更新

训练过程：

```
Advantage
↓
Policy Gradient Loss
↓
Backward
↓
计算梯度
↓
Optimizer.step()
↓
模型参数发生变化
↓
Policy 发生变化
```

对于 Transformer：**Policy = 当前 Transformer 参数所定义的概率分布**

因此：**更新 Transformer 参数 = 更新 Policy**

## 3.4 Vanilla Policy Gradient

Vanilla Policy Gradient 可以理解为最基础、最直接的 Policy Gradient。

核心思想：

- 行为表现好 → 增加对应行为概率

- 行为表现差 → 降低对应行为概率

它最主要解决：**Policy 应该朝哪个方向更新？**

Vanilla Policy Gradient 的问题在于：

> **知道往哪里更新，不代表知道一次应该更新多远。**

如果更新太小：**Policy 改变很少 → 训练速度慢**

如果更新太大：**Policy 概率分布发生剧烈变化** → **原来的行为模式被破坏** → **训练可能震荡** → **性能甚至下降**

因此，接下来需要研究：

> **当我们使用一批已经生成好的训练数据反复更新 Policy 时，新 Policy 与生成这些数据时的 Policy 到底是什么关系？**

这就需要先理解：**Rollout**

# 4. Rollout、Old Policy 与 Importance Sampling

## 4.1 Rollout 是什么？

Rollout 可以简单理解为：**Policy 实际运行、Sampling 后得到的一批强化学习训练数据。**

在大语言模型中，最核心的是：**Prompt + Policy Sampling 得到的 Response + Reward**

实际代码中还可能包含：

```
Prompt
Response
Reward
input_ids
labels
response_mask
old_log_probs
Advantage
...
```

因此：

```
Policy
↓
Sampling
↓
Response
↓
Reward
↓
形成 Rollout
```

其中非常重要的一个信息就是：**old_log_probs**

它记录了：**生成这些 Response 时，Old Policy 对这些 Token 给出的概率信息。**

## 4.2 Old Policy 为什么出现？

假设当前有一个 Policy：**Policy_old**

它进行：

```
Policy_old
↓
Sampling
↓
生成 Responses
↓
得到 Rewards
↓
形成 Rollout
```

因此：**生成当前这一批 Rollout 的 Policy，就记作 Old Policy。**

Old Policy 并不是为了“测量更新幅度”才人为发明出来的概念。

它首先来自一个客观事实：**当前训练数据是某一个特定版本的 Policy 生成的。**

## 4.3 Current Policy 为什么出现？

接下来我们固定这批 Rollout，用它训练模型：

```
Rollout
↓
Policy Gradient Loss
↓
Backward
↓
Optimizer.step()
↓
模型参数改变
```

参数一旦发生更新：

```
Policy_old
↓
参数更新
↓
Policy_current
```

于是：

```
Policy_current ≠ Policy_old
```

因此：

- **Old Policy**：生成当前这批 Rollout 时的 Policy
- **Current Policy**：当前正在被优化的 Policy

## 4.4 关键问题：数据和当前 Policy 不再来自同一个分布

这时出现：

```
Rollout
来自
Policy_old

但是

现在训练的是
Policy_current
```

也就是说：**生成训练数据的 Policy 和当前正在优化的 Policy 已经不完全相同。**

因此：Policy_old 的采样分布 ≠ Policy_current 的当前分布

这就是一种：**Distribution Mismatch**

## 4.5 为什么不能简单把 Old Policy 数据当成 Current Policy 数据？

对于同一个已经采样出的 Action：**Policy_old可能认为它概率很高**

但是更新之后：**Policy_current可能已经认为它概率很低**

所以：**不能完全把 Old Policy 采样的数据，当成 Current Policy 自己重新 Sampling 得到的数据。**

于是问题变成：**如何让 Old Policy 的数据继续合理地用于训练 Current Policy？**

这就引出：**Importance Sampling**

## 4.6 Importance Sampling

Importance Sampling 研究的问题是：**如果样本来自一个概率分布，但我们想估计另一个概率分布下的结果，怎么办？**

一般逻辑：

```
数据来自旧分布
↓
想研究目标分布
↓
根据两个分布的概率关系
重新给样本加权
↓
估计目标分布下的结果
```

放到 Policy Optimization 中：

```
Rollout 来自 Policy_old
↓
现在正在优化 Policy_current
↓
两者分布不同
↓
Importance Sampling
↓
根据新旧 Policy 的概率
对旧样本进行重新加权
```

因此：**Importance Sampling 的主要作用，是补偿 Old Policy 与 Current Policy 之间的采样分布差异。**

它并不是把旧数据真正变成新 Policy 重新采样得到的数据，而是：**通过重新加权进行估计和修正。**

## 4.7 Probability Ratio

对于 Rollout 中实际采样到的一个 Action，可以计算：

```
Current Policy 生成这个 Action 的概率
────────────────────────────
Old Policy 生成这个 Action 的概率
```

即：**ratio = P_current(action) / P_old(action)**

如果使用 log probability：**ratio = exp(current_log_prob - old_log_prob)**

其中：

- old_log_prob = 生成 Rollout 时，Old Policy 对实际采样 Action 的 log probability
- current_log_prob = 现在的 Current Policy 对同一个 Action 的 log probability

## 4.8 Ratio 的作用

#### Ratio第一层作用：Importance Weight

Ratio 首先来自：**Importance Sampling**

它可以用于：

```
Old Policy 数据
↓
Probability Ratio
↓
重新加权
↓
用于估计 Current Policy
```

例如：ratio > 1，说明：Current Policy比 Old Policy更容易产生这个行为

而：ratio < 1，说明：Current Policy比 Old Policy更不容易产生这个行为

因此 Ratio 首先是：**Importance Sampling 的重新加权系数。**

#### Ratio第二层作用：观察行为概率发生了多少变化

因为：ratio = Current Probability / Old Probability

所以它还可以直观反映：**Current Policy 相比 Old Policy，对当前采样行为的偏好发生了多大变化。**

如果：ratio ≈ 1，说明：新旧 Policy对这个行为的概率比较接近

如果：ratio > 1，说明：Current Policy更倾向这个行为

如果：ratio < 1说明：Current Policy更不倾向这个行为

因此 Ratio 有两个紧密相关的意义：

- Importance Sampling 角度：重新加权旧数据

- Policy Optimization 角度：观察新旧 Policy，对当前采样行为的概率变化

但一定要注意：

> **Probability Ratio 只反映当前采样 Action 上的相对概率变化，并不是两个 Policy 整体分布距离的完整度量。**

所以不要简单写成：Ratio = Policy 整体更新幅度

更加准确的是：**Ratio 衡量新旧 Policy 对当前采样行为的相对概率变化。**

## 4.9 为什么 Importance Sampling 还不够？

假设：Policy_current越来越远离Policy_old

那么可能出现：ratio 非常大

或者：ratio 非常接近 0

于是：

```
新旧 Policy 差异越来越大
↓
Importance Weight 越来越极端
↓
估计方差变大
↓
梯度更加不稳定
```

除此之外，还有一个更加重要的问题：

```
Current Policy
离 Old Policy 越远
↓
Old Policy 产生的 Rollout
越难代表 Current Policy 附近的行为
```

所以：**Importance Sampling 可以补偿一定的新旧分布差异，但不意味着 Current Policy 可以无限远离 Old Policy。**

因此还必须解决：**如何避免 Policy 一次更新得过远？**

这就引出：**TRPO**

# 5. TRPO 与 PPO：如何稳定更新 Policy

## 5.1 TRPO 为什么出现？

现在的问题是：

```
Old Policy
生成 Rollout
↓
利用 Rollout
更新 Current / New Policy
```

但是：

```
如果 New Policy
离 Old Policy 太远
↓
旧 Rollout 的代表性变差
+
Importance Ratio 可能极端
↓
训练不稳定
```

因此希望：**Policy 可以更新，但不要一次离旧 Policy 太远。**

这就是 TRPO 的核心思想。

## 5.2 TRPO：Trust Region Policy Optimization

**TRPO：Trust Region Policy Optimization**

核心思想：**在 Old Policy 附近划定一个可信区域，新 Policy 尽量不要一次跳出这个区域。**

可以理解成：

```
Old Policy
↓
周围存在一个 Trust Region
↓
New Policy
在这个区域附近更新
```

它的本质不是：**Policy 完全不能改变**

而是：可以改变，但一次不要改变得太激进

## 5.3 为什么需要 Trust Region？

核心原因：

```
我们手里的数据
来自 Old Policy
↓
如果 New Policy 和 Old Policy 比较接近
↓
Old Rollout 对 New Policy
仍然比较有参考价值
```

反过来：

```
New Policy 离 Old Policy 太远
↓
Old Rollout 对 New Policy
代表性降低
↓
优化变得不可靠
```

所以可以把 TRPO 简化理解成：

> **给 Policy Gradient 加一个比较严格的新旧 Policy 距离控制。**

## 5.4 TRPO 的问题

TRPO 理论上很合理：

```
控制新旧 Policy 距离
↓
训练更加稳定
```

但工程实现比较复杂：

```
复杂约束
↓
优化过程复杂
↓
计算成本较高
```

因此产生一个自然问题：**能不能保留“不要让 Policy 更新太远”的核心思想，但采用更简单的方法？**

于是出现：**PPO**

## 5.5 PPO：Proximal Policy Optimization

**PPO：Proximal Policy Optimization**

PPO 与 TRPO 的总体目标类似：**抑制 Policy 一次发生过大的变化。**

但是方法更加简单，可以粗略理解为：

```
TRPO
↓
严格控制 Policy 距离
↓
实现复杂
```

因此：

```
PPO
↓
使用更简单的目标函数
↓
Ratio + Clip
```

## 5.6 PPO 的核心：Probability Ratio + Clip

PPO 首先计算：

```
Probability Ratio = Current Policy Probability / Old Policy Probability
```

这个 Ratio 可以反映：Current Policy相对 Old Policy，对当前 Action 的概率变化了多少

然后加入：**Clip**

## 5.7 Clip 的作用

Clip 的思想不是：**绝对保证模型参数不能变化超过某个固定值。**

而是：

```
如果 Ratio
还处于合理范围
↓
继续正常优化
```

但是：

```
如果 Ratio
已经变化得过多
↓
Clipped Objective
↓
不再继续给予同样的优化收益
↓
削弱继续大幅改变概率的动力
```

因此可以理解成：**PPO Clip 抑制 Current Policy 相对 Old Policy 对采样行为概率发生过大的变化。**

## 5.8 TRPO 与 PPO 的关系

可以整理成：

```
Vanilla Policy Gradient
↓
更新可能过大
↓
TRPO
↓
使用 Trust Region
严格限制新旧 Policy 差异
↓
但实现复杂
↓
PPO
↓
Probability Ratio + Clip
↓
用更简单的方法抑制过大的 Policy 变化
```

所以：TRPO和PPO主要解决的是：**Policy 怎么稳定更新？**

# 6. 经典 PPO：Advantage 怎么得到？

到这里解决了：**PPO 怎么控制 Policy 更新**即：**Ratio + Clip**

但 PPO 还有另一个问题：**Advantage 从哪里来？**

因为 Policy Gradient 仍然需要知道：**哪个行为好，哪个行为差**

## 6.1 经典 PPO 通常采用 Actor-Critic

经典 PPO 通常放在：**Actor-Critic**框架中。

其中：**Actor=Policy**

对于大语言模型：**Actor / Policy = 根据 Prompt，生成 Response**

**Critic作用是估计：当前 State 下，未来正常情况下大概能够获得多少 Return。**

通常写成：**V(s)**

## 6.2 Critic 为什么可以作为 Baseline？

因为：V(s)

可以理解成：**在当前 State 下正常情况下预期能获得的未来回报。**

因此：Advantage = 实际表现 - Critic 预测的正常表现

所以 Critic 的一个重要作用是：**为 Advantage 提供 Baseline。**

## 6.3 最简单的 Advantage 思路

最简单可以理解成：

```
Advantage = 实际结果 - Critic 预测的正常水平
```

但是问题来了：**“实际结果”到底应该看多远？**

这就涉及：**Bias–Variance Trade-off**

**极端情况一：更多依赖真实长期结果**

如果更多依赖完整 trajectory 最终真实发生的结果：**真实长期 Return → 更少依赖 Critic 的预测**

优点：**更加依赖真实发生的结果，Bias 较低**

缺点：

```
前面的 Action
需要用很远以后的结果评价
↓
中间包含很多随机行为
↓
Credit Assignment 更困难
↓
不同 trajectory 差异较大
↓
Variance 较高
```

因此：更多依赖真实长期 Return = Bias 较低 + Variance 较高

**极端情况而二：更多依赖 Critic Bootstrap**

另一种方式是：**更多利用短期 Reward + Critic 对下一 State 的 Value Estimate**

这样不需要一直依赖非常远的最终结果。

优点：估计通常更稳定，Variance 较低

缺点：

```
更加依赖 Critic
↓
如果 Critic 预测不准确
↓
产生系统性误差
↓
Bias 可能更高
```

因此：**更多依赖 Critic Bootstrap = Variance 较低 + Bias 可能更高**

## 6.4 Bias–Variance Trade-off

于是出现：

- 真实长期结果：Bias 低，Variance 高

- Critic 短期预测：Bias 可能更高，Variance 更低

因此需要在两者之间进行折中，这就引出：GAE

## 6.5 GAE：Generalized Advantage Estimation

**GAE：Generalized Advantage Estimation**

核心思想：**综合不同时间尺度的信息，在 Bias 和 Variance 之间取得折中，从而得到更稳定的 Advantage Estimate。**

它不是重新创造一个完全不同的 Advantage。

而是：

```
真实 Trajectory 信息 + Critic 的 Value Estimate
↓
GAE
↓
Advantage Estimate
```

更加准确的结构是：

```
                 Trajectory
                    │
          ┌─────────┴─────────┐
          │                   │
          ↓                   ↓
       Rewards              States
          │                    │
          │                    ↓
          │                 Critic
          │                    │
          │                    ↓
          │               V(s), V(s')
          │                   │
          └─────────┬─────────┘
                    ↓
                   GAE
                    ↓
               Advantage
```

因此：**GAE 不是只相信最终结果，也不是只相信 Critic，而是在不同时间尺度的估计之间做折中。**

## 6.6 经典 PPO 的完整流程

因此经典 PPO 可以整理成两个部分。

### 第一部分：计算 Advantage

```
Policy_old
↓
Sampling
↓
Trajectory / Response
↓
得到真实 Rewards / States
            +
Critic 计算 Value Estimate
↓
GAE
↓
Advantage
```

### 第二部分：更新 Policy

```
Advantage
+
Current / Old Policy Probability
↓
Importance Ratio
↓
PPO Clip
↓
Policy Gradient Loss
↓
Backward
↓
Optimizer.step()
↓
更新 Policy
```

完整流程：

```
Policy_old
↓
Sampling
↓
Trajectory / Response
↓
Rewards + States
      │
      └────→ Critic → Value Estimate
                    │
                    ↓
                   GAE
                    ↓
                Advantage
                    │
                    ↓
Current Policy Probability
+
Old Policy Probability
↓
Importance Ratio
↓
PPO Clip
↓
Policy Gradient Loss
↓
Backward
↓
Optimizer.step()
↓
New Policy
```

## 6.9 经典 PPO 的额外成本

经典 Actor-Critic PPO 的一个明显成本是：**不仅要训练 Policy，还要训练 Critic**

这意味着：

```
Critic / Value Head
↓
额外前向计算
↓
额外训练
↓
额外显存
↓
更复杂的训练系统
```

于是产生一个自然问题：**能不能不训练 Critic，也构造出能够用于 Policy Gradient 的 Advantage？**这就是 GRPO 的关键出发点之一。

# 7. GRPO：不用单独 Critic 得到 Advantage

## 7.1 GRPO 是什么？

**GRPO：Group Relative Policy Optimization**

它与经典 Actor-Critic PPO 一个非常重要的区别是：

经典 PPO：Critic + GAE →Advantage

而：GRPO：同一个 Prompt，Sampling 多个 Responses → 组内比较 →Group Relative Advantage

因此：**GRPO 不依赖单独训练的 Critic，而是通过同一个 Prompt 下多个 Response 的相对 Reward 构造 Advantage。**

## 7.2 GRPO 为什么要对同一个 Prompt 多次 Sampling？

给定：一个 Prompt，GRPO 不只生成一个 Response。

而是：

```
同一个 Prompt
↓
Policy Sampling 多次
├── Response 1
├── Response 2
├── Response 3
├── ...
└── Response G
```

然后分别计算：

```
Response 1 → Reward 1
Response 2 → Reward 2
Response 3 → Reward 3
...
Response G → Reward G
```

这样就可以比较：**对于完全相同的 Prompt，这几个 Response 谁表现得更好？**

## 7.3 Group Baseline

得到一组 Rewards：

```
R1
R2
R3
...
RG
```

可以利用这一组 Response 的整体表现建立参考标准。

最容易理解的形式是：**Group Baseline = 这一组 Rewards 的平均值**

然后：Relative Advantage_i = Reward_i - Group Baseline

因此：某个 Response高于组内平均，Advantage > 0

而：某个 Response低于组内平均，Advantage < 0

实际 GRPO 中还常见：根据组内标准差，进一步归一化

但核心思想不变。

## 7.4 Group Relative Advantage

GRPO 关注的不是：**这个 Response 的绝对分数是多少？**

而是：**在同一个 Prompt 生成的这一组 Responses 中，它的表现相对其他 Responses 怎么样？**

所以：Reward → 组内比较 → Group Relative Advantage

## 7.5 GRPO 为什么可以不训练 Critic？

经典 PPO：

```
当前 State
↓
Critic
↓
估计正常水平
↓
构造 Advantage
```

GRPO：

```
同一个 Prompt
↓
Sampling 多个 Responses
↓
得到一组 Rewards
↓
利用组内统计作为参考
↓
构造 Relative Advantage
```

所以：**GRPO 用组内相对 Reward 构造 Advantage，从而避免单独训练 Critic。**

可以粗略理解成：**更多 Sampling 计算 → 换掉 Critic 的训练和显存成本**

但不能简单写成：**多 Sampling = Critic**

更加准确的是：**GRPO 通过 Group Relative Reward 构造 Advantage，因此不再依赖独立的 Value/Critic 模型。**

## 7.6 GRPO 是否还需要 Policy Gradient？

GRPO 需要 Policy GradientGRPO 并没有抛弃：Policy Gradient

它最重要的变化之一是：Advantage 怎么得到

经典 PPO：Critic + GAE → Advantage

GRPO：Group Rewards → Group Relative → Advantage

最后都需要：Advantage → Policy Gradient → 更新 Policy

## 7.7 GRPO 是否还需要 Ratio 和 Clip？

典型 GRPO 使用 PPO-style 的 Policy Optimization 思路。

因此仍然可以有：

```
Old Policy Probability + Current Policy Probability
↓
Importance Ratio
↓
Clip
↓
Policy Gradient Loss
```

所以 GRPO 主要改变的是：Advantage Estimation，而不是完全推翻 PPO 的 Policy Update 思想。

## 7.8 GRPO 完整训练流程

整体流程：

```
一个 Prompt
↓
Policy
↓
Sampling G 次
↓
得到 G 个 Responses
↓
Reward Function
↓
得到 G 个 Rewards
↓
计算组内统计量
↓
Group Baseline
↓
Group Relative Advantage
↓
计算 Current Policy
对 Response Token 的概率
↓
与 Rollout / Old Policy 概率比较
↓
Importance Ratio
↓
Clip
↓
Policy Gradient Loss
↓
Backward
↓
Optimizer.step()
↓
更新 Policy
↓
下一轮 Sampling
```

因此：**GRPO = Group Relative Advantage + Policy Gradient + PPO-style 稳定更新机制。**

# 8. PPO 与 GRPO 的整体关系

## 8.1 两条核心主线

到这里，可以把所有知识重新压缩成两条主线。

### 主线一：这个行为到底好不好？

```
Reward
↓

↓
Advantage
↓
判断行为应该被鼓励还是抑制
```

在不同算法中，参考水平的来源不同。

经典 PPO：Critic + GAE → Advantage

GRPO：Group Relative → Advantage

### 主线二：知道行为好坏以后，怎么稳定更新 Policy？

```

↓

↓

↓

↓
Trust Region
↓

↓

```

↓

```

同时：

```

↓

↓

↓
Policy Gradient
```

合起来：

```

            \
             → PPO Policy Loss → Policy Update

↓
Clip
↓

合起来：

```

↓

            \
             → GRPO Policy Loss → Policy Update
            /

```

## 8.4 PPO 与 GRPO 最核心区别

可以压缩成：经典 PPO = Critic + GAE 得 Advantage + Ratio + Clip 更新 Policy

而：GRPO = Group Relative 得 Advantage + PPO-style Ratio + Clip 更新 Policy

所以 GRPO 最重要的变化不是不要 Policy Gradient，也不是不要 PPO 的全部思想

而是：**不再依赖单独训练的 Critic，而使用同一 Prompt 下多个 Response 的组内相对 Reward 来构造 Advantage。**
